# core/ -- Strategy, executor, timing, regime

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `core/` -- `Strategy` (lumibot hook names/signatures, broker facade, paper/live runners), `StrategyExecutor` (single-threaded session loop), `timing.py` (pure `sleeptime` parsing and tick maths), `Strategy.iteration_start_time` (a market `time`, default `None` = the open) moves each session's first `on_trading_iteration` -- the other hooks keep their times, a start in the closing window skips that session's iterations, a mid-session start after it iterates at once -- `events.py` (stream-thread → executor-thread order-event queue), `indicators.py` (`strategy.indicators.<pandas-ta name>(asset, ...)`, no cache), `regime.py` (**pure** market regime classifier: `RegimeParameters`, `classify_regime`).

## Gotchas

- **Every strategy gets a market regime by default, and nothing trades on it.** The executor calls `Strategy._refresh_regime()` once per session (before `before_market_opens`, also on a mid-session start, whatever the `sleeptime`): `core/regime.classify_regime` reads `regime_params.min_bars` (273) daily closes of `benchmark_symbol` and gives `strategy.regime` = 1 bullish / 0 neutral / -1 bearish (`None` until there is enough history). Trend is the close and SMA50 against SMA200; a 20-day realized volatility strictly above its own 80th percentile over 252 days caps a bullish read at neutral and never makes one bearish. It is logged in every mode and charted with `add_line("Regime", ...)` in backtests only (the dashboard's Trades chart and the Returns tab's Cumulative Returns chart draw only that line, as its own row with bands, and ignores every other line in `indicators.parquet`: `charts.REGIME_PANE` must equal `regime.REGIME_LINE`). A failure keeps the previous value and never costs a session, and it is not a hook (no `on_bot_crash`). `Strategy.run_backtesting` raises a daily run's `warmup_trading_days` to at least `regime_params.min_bars + REGIME_WARMUP_SLACK` (283; `warmup_calendar_days`' fixed holiday buffer under-covers a 13-month span, so exactly 273 left some start dates 1-3 sessions short): the runner's eager benchmark load would otherwise cache a frame too short for it. For any other timestep the warmup is left as asked (raising it would widen every minute download) and only the benchmark's daily frame is preloaded over the regime window, with one extra `load(..., "day")` before `run_backtest`. Using the regime to size or gate a strategy is a new design decision, not a default.

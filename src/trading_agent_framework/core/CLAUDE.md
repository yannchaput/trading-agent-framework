# core/ -- Strategy, executor, timing, regime

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `core/` -- `Strategy` (lumibot hook names/signatures, broker facade, paper/live runners), `StrategyExecutor` (single-threaded session loop), `timing.py` (pure `sleeptime` parsing and tick maths), `Strategy.iteration_start_time` (a market `time`, default `None` = the open) moves each session's first `on_trading_iteration` -- the other hooks keep their times, a start in the closing window skips that session's iterations, a mid-session start after it iterates at once -- `events.py` (stream-thread → executor-thread order-event queue), `indicators.py` (`strategy.indicators.<pandas-ta name>(asset, ...)`, no cache), `regime.py` (**pure** market regime classifier: `RegimeParameters`, `classify_regime`, `regime_by_session`), `regime_data.py` (`RegimeSource`, `YahooRegimeData`: SPY/VIX/VIX3M closes plus optional VIXY from Yahoo), `regime_scorecard.py` (**pure** `score` against SPY swing falls) and `regime_cli.py` (`uv run regime scorecard|recompute`).

## Gotchas

- **Before every tick the executor settles unknown orders** (`StrategyExecutor._settle_unknown_orders`): `broker.settle_unknown_orders()` (no-op except `TastytradeBroker`, which looks up orders whose submit/replace outcome was unknown and adopts or fails them, never resending), then the order events that produces are dispatched, so the tick sees the outcome. A failure is a WARNING and the tick still runs, with no `on_bot_crash` (a framework step like the regime refresh). It runs on the executor thread, per tick (daily for bull_bear and cross_momentum), not between ticks.
- **Every strategy gets a market regime by default, and nothing trades on it.** The executor calls `Strategy._refresh_regime()` once per session (before `before_market_opens`, also on a mid-session start, whatever the `sleeptime`) and sets `strategy.regime` = 1 bullish / 0 neutral / -1 bearish (`None` until there is enough history). The inputs are Yahoo's SPY, `^VIX`, `^VIX3M` and VIXY (optional: `nan` when Yahoo has none, with one warning; a non-positive VIXY close counts as missing, while a non-positive VIX or VIX3M close still fails the refresh) daily closes in every mode and for every strategy, whatever its own price source and `benchmark_symbol` (the regime labels the market, so it reads the same for all of them): `Strategy.regime_source` (a `core/regime_data.RegimeSource`, `YahooRegimeData()` by default, one batched download per day, VIX, VIX3M and VIXY forward-filled up to 5 sessions onto SPY's sessions; tests assign a `FakeRegimeSource` and the autouse conftest fixture patches `core.strategy.YahooRegimeData`) is asked for `regime_params.min_bars` (503) closes strictly before `clock.now()` in market time's date, so a backtest never sees a session's own close and a mid-session start gives the morning's answer. `core/regime.classify_regime` scores four conditions, one point each (VIX >= VIX3M; VIX >= 1.5 x its 252-session median; SPY below its SMA50; SPY at least 5% under its 252-session high). Bearish at score >= 2, neutral at 1, bullish at 0; once bearish it tracks the episode's lowest SPY close and ends at an 8% bounce off that low (after which it cannot turn bearish again until SPY closes below the low or the score hits 0) or when the score drops under 2; a bullish/neutral change shows only after 3 sessions. It is stateless across calls: each refresh replays the state machine over the last 252 sessions, so a restart or a backtest started on any date gives the uninterrupted answer. It is logged in every mode with the score and its components, and charted with `add_line("Regime", ...)` in backtests only (the dashboard's Trades chart and the Returns tab's Cumulative Returns chart draw only that line, as its own row with bands, and ignores every other line in `indicators.parquet`: `charts.REGIME_PANE` must equal `regime.REGIME_LINE`). A failure (`RegimeDataError`, `ValueError`) keeps the previous value with a warning and never costs a session, and it is not a hook (no `on_bot_crash`). `Strategy.run_backtesting` still raises a daily run's `warmup_trading_days` to at least `DAILY_WARMUP_FLOOR` (283) and, for other timesteps, preloads the benchmark's daily frame over that window: the regime no longer needs either (it reads Yahoo on its own), but strategies (for example earnings_drift's recorded 283) and the runner's daily benchmark read rely on them; removing them is a separate decision. The same refresh also keeps the full `RegimeReading` in `strategy.regime_reading` and sets `strategy.market_fall` (`bool | None`): `utils/helpers.in_market_fall` (the "VIX alone" early warning, VIX/VIX3M or a VIXY jump) on the same 503-row slice, set together with the regime, kept on a failed refresh, logged as `Market fall warning ON|OFF`, not charted, and nothing trades on it. Using the regime to size or gate a strategy would be a new design decision, not a default. `uv run regime recompute` and `scorecard` always use the default `RegimeParameters()`: a strategy overriding `regime_params` would get a chart that disagrees with its own backtest, so such an override must come with its own recompute. A VIX/VIX3M gap longer than 5 sessions anywhere in the downloaded span makes the scorecard/recompute exit 1, while a backtest only loses the sessions whose 503-row window contains it.
- **Every buy passes one budget check, in `Strategy.submit_order` (and so `submit_orders`, which loops over it).** `Strategy.spendable_cash()` = `min(buying_power, cash + unfilled open sells - unfilled open buys) - BUY_BUFFER x portfolio_value` (`BUY_BUFFER` = 2%, `utils/helpers.py`, not a parameter: a strategy that wants more cash on hand holds a sleeve such as SHV in its own allocation). Open orders count for their unfilled part only, at their limit price, else the last price; a stop or trailing-stop sell brings no credit and is not quoted (earnings_drift and vwap_pullback hold one per position: quoting them cost a data request per sizing call and a quote error zeroed every candidate); a stop buy is priced and debited; an order with no price estimate counts as 0. It reads `broker.get_account()` FIRST and `broker.tracker.get_active_orders()` second: a sell filling in between is then counted nowhere, never twice (the reverse order counts it twice). `spendable_cash(account=...)` takes an account snapshot the caller has just read instead of reading it again (`get_account_balance`, vwap_pullback's `enter_long`); the open orders are still read after it, so that order holds. The 2% is a sizing reserve, not a second wall: the check itself stops at `spendable_cash() + BUY_BUFFER x portfolio_value` (the real money), so a buy sized to exactly `spendable_cash()` still passes when a price ticks up before it is sent (the buffer absorbs drift; `submit_buy`'s retry only handles a tick bigger than 2%). A buy above that raises `InsufficientFundsError` (`utils/errors.py`, an `OrderValidationError`) carrying `spendable` and `max_quantity`; sells, notional buys and buys without a price pass unchecked (the broker stays the last net). Callers size with `spendable_cash()` instead of their own formula; it may be negative (fully invested).
- **`run_backtesting` resolves its defaults from `parameters`.** `start`, `end`, `budget`, `benchmark`, `slippage` and `warmup_trading_days` take the argument, then `self.parameters["backtesting_start"|"backtesting_end"|"budget"|"benchmark_symbol"|"slippage"|"warmup_trading_days"]`, then the class attribute (`backtesting_start`, `backtesting_end`, `budget`, `benchmark_symbol`, `backtesting_slippage = Decimal("0.0005")`, 5 bps per side; warmup 0). A strategy's `run_backtesting` override therefore passes only `data_source`, `preload_assets`, `timestep` and `agent_telemetry`; a strategy that needs the window before the run starts (a universe pre-step, a no-look-ahead cutoff: cross_momentum, bull_bear, earnings_drift, insider_trades) reads it through `Strategy.resolved_window(start, end)`, the same resolution `run_backtesting` uses (a bound of `None` counts as not given; a missing bound raises `ConfigurationError`), so the two cannot disagree about which window is simulated. A toy strategy whose test needs exact fill prices sets `backtesting_slippage = Decimal(0)`. The runner records the slippage in `settings.json["slippage"]`.
- **`Strategy.run_file(name)` and `Strategy.state_file(name=None)` are the two path helpers.** `run_file` is `logs/<strategy>/<mode>/<run_id>/<name>`, `None` without a `run_id` (a strategy outside a runner writes no log). `state_file` is `data/<name or strategy>_state_<mode>.json`.

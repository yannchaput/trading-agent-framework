# dashboard/ -- Streamlit app

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `dashboard/` -- Streamlit app (`uv run dashboard`, entry `app.py`: dark theme, logo, `st.navigation(position="top")` over four tabs). **Live** and **Paper** (`_pages/account.py`, one `page_account(mode)`): the sidebar `selectbox` (a plain session key per mode keeps the choice across tabs) lists the strategies with an `env/.env.<strategy>.<mode>` file whose `BROKER` is alpaca and that opts in with `DASHBOARD_DISPLAY=true` (`true`/`1`/`yes`; missing means hidden, so a retired strategy's file stays off the picker without any API call -- the agent never reads it); `account_reader.py` (Streamlit-free) reads that file's keys with `dotenv_values` -- never `load_dotenv`, so no key reaches `os.environ` -- and calls three Alpaca GETs through read-only Protocols (`/account/activities` FILL+FEE+DIV+DIVNRA -- dividends and their withholding count as realized on their day, IEX **RAW** daily bars since fills are unadjusted, positions); `pnl.py` (pure) replays the fills at average cost -- `AverageCostBook`, shared with `reader.load_session_pnl` -- into realized P&L per US/Eastern day and the unrealized P&L at each day's close. Each `days` row also carries `change` (the day's P&L: realized plus the move of the unrealized level since the previous close) -- `realized + unrealized` is NOT a day's P&L (one is a flow, the other a level), so the chart plots `change` as a line with sign-coloured markers (no cumulative curve: it was misread), and the first row of a window still diffs against the day before it. Alpaca's portfolio history labels a close with the *next* day's date (its `954.76` under the 22nd is the 21st's close), and its `profit_loss` counts deposits as gains. (today: the replayed shares at the position's `current_price` against the replayed cost, so Total keeps one cost basis -- Alpaca re-bases overnight positions to compressed FIFO; its own `unrealized_pl` is used only for a position the fills do not explain, and is shown beside when it differs), and reports fills that do not explain the positions. The caption says which account the keys hit (`account_reader.account_is_paper`) and warns when that is not the tab's mode. Under that plot, `components/charts.account_returns_chart` draws the strategy's and SPY's daily move against the day before in percent (strategy cyan, SPY the backtest yellow, each line's last value written at its end): `pnl.daily_returns_pct` divides a day's `change` by the account's equity at the previous close and SPY's close by its previous close, over the whole history and cut to the window afterwards so its first day keeps a base; `account_reader.load_strategy_return_bases` fetches the equity (`/account/portfolio/history` 1D, whose labels are the *next* calendar day, moved back one by `fetch_equity_closes`) and SPY's closes through today from `strategies/common/yahoo_daily_bars.YahooDailyBars` -- the backtests' own bars (consolidated official closes, dividend-adjusted), not the IEX closes the fills' unrealized P&L uses (cached 5 min like the P&L; an Alpaca or Yahoo failure warns and leaves only this plot out). Sidebar **Start date**/**End date** inputs (bounded by the first and last day of the history, kept per mode under `account_window_<mode>`) fit the plot and the Realized card to the window via `pnl.days_between`; Unrealized now is always the current figure. Fetched on demand (`st.cache_data`, 5 min `ttl`, Refresh clears it), no polling. Backtesting stays the default tab (`app.DEFAULT_PAGE`). **Backtesting** (`_pages/backtesting.py`, the sidebar buttons and the scorecard/detail/side-by-side router): `reader.py` reads `logs/<strategy>/<mode>/<ts>_<mode>/` run directories, `memory.sqlite` and `llm_stats.sqlite` read-only into `models.py` types. **Models** (`_pages/models.py`): `benchmark_reader.py` (Streamlit-free) reads the sibling `benchmark-vllm-models/results/<YYYYMMDD-HHMMSS>/` runs (`meta.json` + `summary.json`; `<model>.jsonl` for the per-scenario drill-down, message traces never loaded) -- default next to the project root, override with `uv run dashboard --benchmark-dir PATH` (`cli.py` forwards it after `--`; no env var). The dark theme is `cli.THEME_ARGS` (`--theme.*` flags, since `.streamlit/config.toml` would be read from the cwd) plus `components/charts.CHART_TEMPLATE` -- never `plotly_white`. Run Detail's **Agents** sub-tab (before Parameters; `components/tables.render_reviews_table(ref)`, `reviews_reader.py` Streamlit-free) exists only for a run with a `reviews.jsonl` (`has_reviews`; written by bill_ackman and bull_bear into the run directory; other runs get no tab) and shows it as one table row per review -- only the fields both schemas fill (date, status, stage, holdings, targets, forced exits, orders, error; holdings come from `holdings` or the `held` flags of `debate_set`) -- above a clickable list of the reviews (newest first, a radio over record indices) beside the selected review's raw record as JSON; unreadable lines are counted, not raised. `components/` (charts/metric cards/tables) render both tabs. Read-only -- never writes back into a run. `AppTest.switch_page` can't reach callable pages: page tests use `AppTest.from_function`, tabs are checked via `app.NAV_PAGES`.

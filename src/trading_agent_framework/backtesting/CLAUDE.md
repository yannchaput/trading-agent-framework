# backtesting/ -- the third trading mode

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `backtesting/` -- the third trading mode. `clock.py` (`BacktestClock`, simulated time), `broker.py` (`BacktestBroker`, simulated fills via `fills.py`'s pure OHLC rules), `ledger.py` (fills/equity/indicator lines, `Decimal`), `data/` (`BacktestDataSource` ABC, `CachedDataSource`, `YahooBacktestData` default, `AlpacaBacktestData`, `YearChunkedData` in `chunked.py`: minute bars one 365-day chunk at a time, each fetched from 30 days before its start, for windows over a year; day bars and sessions from one whole-window source), `warmup.py` (**pure** `warmup_calendar_days()`, approximating a trading-day lookback as a calendar-day buffer), `metrics.py` (vectorbt reporting) and `report.py` (writes the run to `logs/<strategy>/backtesting/<ts>_backtesting/`) are the pure-to-I/O layers; `runner.py` orchestrates a run and `Strategy.run_backtesting()` is the public entry point. Both `Strategy.run_backtesting()` and `runner.run_backtest()` accept a `warmup_trading_days` parameter that widens only the eager benchmark data load's start bound (via `warmup_calendar_days()`), never the simulated `[start, end]` session window itself. `MarketClock.max_wait_slice` (`60.0` live, `math.inf` simulated) is the executor's only backtest seam.
- `backtesting/placeholder.py` -- `PlaceholderBroker`: what `main.py` builds a strategy with in backtesting mode; no network.

## Gotchas

- **Backtest news is GDELT before 2026-04-29 and Alpaca from then on** (`backtesting/news.py`; `BacktestBroker.news_provider()`'s default, `news_source=` overrides it). Alpaca's archive starts 2026-04-29, so older windows used to get silently empty news. `GdeltNewsProvider` reads `cache/gdelt/gkg_stockmarket/<YYYY>/<YYYY-MM-DD>.parquet` (UTC days, `stamp <= end`: no look-ahead) and fails loud (`BrokerError`) when that directory is missing. A window is cut to the 31 days before `end` (`MAX_WINDOW_DAYS`): it reads one file per day, and a 2-year window took 130 s and 0.9 GB. It has titles only (no summary, no body, `include_content` is ignored; each article is marked `titles_only`, which `search_news` turns into an instruction for the model on any call); a missing title (all of it before 2019-09-23) is built from the URL slug (`slug_title`). A symbol matches by `(EXCHANGE:TICKER)` tag or whole-word company name (SEC `cache/sec/company_tickers.json`: today's names, `ALIASES` for SPY/QQQ/DIA...); with no symbols only US-market titles without a ticker tag are kept. `CutoffNewsProvider` routes a window by date and merges a spanning one. Runs on GDELT news are not like-for-like with Benzinga-news runs.

- **`BacktestBroker` is single-threaded, with a tripwire, not a lock** (`_one_thread`): `get_account` and `pull_positions` may run on several threads at once (parallel analysts read the account); a write (`_submit_order`, `cancel_order`, `modify_order`, `close_position(s)`, `on_advance`) next to another thread's call raises `BacktestError`, and the next `on_advance` raises again, because `submit_order`'s tool turns every exception into `{"error"}`. It locks nothing, so a backtest behaves like a live run; the callers serialize themselves (`AgentManager` for trading agents, `agents/CLAUDE.md`).
- **cross_momentum and bull_bear backtests trade a point-in-time universe; the other universe strategies still use today's file.** The two build (or reuse) the monthly top-1,200 history for their window in `run_backtesting` before the runner starts, and read the list of each review's month (`strategies/common/CLAUDE.md`, `strategies/cross_momentum/CLAUDE.md`). Rank is by the 63 sessions' traded dollar volume before the month, so no future data reaches a date; this is a universe choice made before the `BacktestDataSource.bars()` chokepoint, not a replacement for it. bill_ackman, vwap_pullback and earnings_drift (and its baseline) backtest on the universe file built today, which holds today's winners: compare their backtests with that in mind. Their preload is `UniverseBacktestData` (`strategies/common/universe_backtest_data.py`, a `YahooBacktestData` that loads in batches and raises `UniverseHistoryError` when over 1% of the symbols stay empty, because `YahooBacktestData.load` itself only warns about an empty frame); the others keep `YahooBacktestData`. Remaining bias in both modes: stocks delisted inside the window are missing from Yahoo. A run's `settings.json` says which one it used (`parameters.universe.mode`); a run without it used today's list.
- **`BacktestBroker._source_bars` is the gate** (design spec §5.2): the single place the broker reads a `BacktestDataSource`, and the one defensive check that no returned row closes after the cutoff. Route any new price path through it rather than calling `self._data_source.bars(...)` directly. A source that can't map a bar to a real session must raise `BacktestDataError` rather than fall back to a plausible-looking index -- silently early data is the failure mode this whole subsystem exists to prevent. `get_bars(..., "minute", include_after_hours=False)` keeps only regular-session rows (close-stamped: `open < ts <= close`, sessions from the data source) and re-reads a longer window through the gate until `length` such rows remain -- Alpaca's minute frames carry extended hours, so the raw last `length` rows covered too few sessions.
- **`AlpacaBacktestData._frames` is keyed by `(asset, timestep)`, never by asset alone.** `runner._run()` eagerly loads the benchmark asset at the strategy's own timestep (e.g. `"minute"`), then separately calls `bars(..., "day")` on the same asset for annualization; an asset-only key would silently reuse the minute frame relabeled as daily data and corrupt `metrics.json`'s benchmark-relative figures (Sharpe, Sortino, CAGR, alpha/beta). Any new per-timestep cache in the backtesting data layer needs the same two-part key.
- **`run_backtesting(data_source=...)` takes an instance or a `(start, end)` factory, never the window itself.** A class (`YahooBacktestData`, `AlpacaBacktestData`) or `partial(YearChunkedData, inner=AlpacaBacktestData)` is called as `data_source(warmup_start, end)` (`core/strategy.py`), because only `run_backtesting` knows the warmup-widened start. A source needing extra constructor arguments is bound with `functools.partial` (keyword-only, as `YearChunkedData`'s `inner`, or `UniverseBacktestData`'s `record`), not built up front.
- **One clock advance can span many bars** (minute bars under a sleeptime of hours: `BacktestClock.wait` jumps once and calls `on_advance` once). `_process_pending` therefore walks every bar closed since an order was last evaluated (`_bars_after`), so an order fills on the first bar after submission (next-bar-open, spec §2) and the forming-bar skip costs one bar, not the whole jump. Never evaluate fills on "the latest bar before the cutoff": that filled market orders at hours-old prices, missed limits touched mid-jump, and let a buy fill before the sell submitted ahead of it (rejected for cash).
- **Backtest `start`/`end` must be timezone-aware** (`MarketSession` enforces tz-aware bounds); `run_backtest` validates this up front and says so, so a naive `datetime.now()` never reaches a comparison deep in the clock. **`start`/`end` are inclusive by calendar DATE**: a bare-midnight `end` (how `backtesting_end` is spelled) means "through the end of that day", `sessions()` includes that date's session, and `run_backtest` therefore reads the benchmark up to the last session's close, not the exact instant `end` (a bar is stamped at its close, after that midnight, so cutting there drops the last session). Never compare `end` as an instant against a bar timestamp.
- **`equity.parquet` and `metrics.json` are built from the SAME session-reduced series** (`runner._session_equity_samples`): exactly one row per trading session, stamped at the session's close. `BacktestBroker.on_advance` samples equity on every clock advance, so the raw ledger is oversampled several-to-one; feeding that to either consumer silently understates annualised metrics and breaks the benchmark join. Don't hand `ledger.equity` straight to `report.write_equity`.
- **A RUNNING backtest has only `backtest.log` and (bull_bear) `reviews.jsonl`.** `equity.parquet`, `trades.parquet`, `metrics.json`, `settings.json` and `description.json` are written when the run ends. Meanwhile the portfolio value is in `backtest.log` (`Trading iteration of <strategy> at <date>T12:00... portfolio value: N`, the noon value) and `uv run bull-bear-scores <run_dir>` works on the partial `reviews.jsonl`. The model is recorded nowhere but the log (the first `qwen...` in `backtest.log`).
- **Compare backtests at the same close.** A total covers the run's own window, so a run that ends later can include a crash the others miss (the 2026-10-05 and 2026-10-16 runs differed by the 10-02 to 10-16 momentum crash, 15 to 21% for every run). Cut every run to the shortest common end date from `equity.parquet`.
- **A run does not record its git commit.** To know which code produced a run, compare its directory timestamp with `git log --format='%h %ad %s' --date=format:'%m-%d %H:%M'`.
- **`BacktestBroker` is a long-only cash account, and rejects in two places.** At fill time a buy that costs more than cash (fees included) or a sell larger than the holding is rejected whole (order error status + `OrderEvent.ERROR`, nothing moves); that check stays the authority, since it is the moment cash actually moves. At *submission* time `_projected_rejection_reason` additionally raises `OrderValidationError` for what is already certainly impossible, so a caller finds out in the same iteration instead of a session later -- which matters for an LLM agent, whose only feedback channel is the tool's return value (`submit_order` turns the exception into `{"error": ...}`). The submission check works off ESTIMATED prices (limit price, else the latest close via `_source_bars`) and so deliberately lets through anything it cannot price. It does not break the rebalance pattern that put the hard check at fill time, because `_projection` *credits* pending sells: orders fill in submission order, so sells submitted before buys really do fund them. No shorts, no margin, cash never goes negative. Paper/live trading is unaffected -- all of this lives in `backtesting/broker.py`; Alpaca does its own checks.
- **A backtest position's `avg_fill_price` is its average cost, as Alpaca (`avg_entry_price`) and IBKR (`averageCost`) report it**: a buy averages in at the fill price (fees excluded), a sell leaves the cost of the remainder unchanged, a full sell drops the position and the next buy starts a new cost (`BacktestBroker._apply_to_position`). It used to be the last fill price, buys and sells alike, which made any cost-based figure (the `Rebalancer`'s estimated sell P&L, `earnings_drift`'s adopted `entry_price`) wrong only in backtests.
- **Backtest fees come from `BROKER`, per order, and differ by side.** `Strategy.run_backtesting(fees=None)` resolves `TradingFeeFactory.from_env()`, so the backtest env file's `BROKER` (Alpaca when unset) picks the schedule; `BacktestBroker(fees=None)` (tests) charges nothing. A sell pays SEC (on value) + FINRA TAF (capped per order) + CAT; a buy pays CAT only -- plus the broker's commission on both (IBKR `max($1, $0.005/share)`, Alpaca $0, Tastytrade a clearing fee of $0.0008/share, or $0.10 flat instead for a fractional order, as of 2026-10-28; its $5 fractional minimum is not modelled). Each side rounds up to the cent. Rates are dated constants in `brokers/fees.py` (2026-09-28): an older backtest period pays today's rates.
- **In backtesting, `get_account()` nets only `buying_power`, never `cash`.** `buying_power` is `_projection(now).cash` (settled cash, minus what pending buys have committed, plus what pending sells will bring in), because backtest fills land a session after submission and a strategy sizing against settled cash double-spends it. `cash` and `portfolio_value` stay raw on purpose: `Strategy.get_cash()` reads `cash`, and `Strategy.spendable_cash()` adds the unfilled part of every open order to it (open sells credited, open buys debited), so netting `cash` would count the pending orders twice. Counting only the part still to fill matters live: market sells fill within seconds and their proceeds are already in Alpaca's `cash`. In a backtest nothing fills before the next session, so every pending order counts in full and the cash term approximately equals the projection (the projection also nets the pending orders' fees, buys' and sells' alike, which the cash term does not; that is why cross_momentum caps each buy with a fresh `spendable_cash()`). No strategy does this arithmetic itself (cross_momentum, earnings_drift and vwap_pullback size from `spendable_cash()` too). Agents do not either: `get_account_balance` reports `spendable` (`Strategy.spendable_cash()`: the smaller of `buying_power` and `cash` after open orders, less 2% of the book), and `Strategy.submit_order` refuses a buy above it. On a live Alpaca margin account `buying_power` is a multiple of equity, which is why it is only ever one side of that minimum. `NewsBinaryStrategy` also puts a `portfolio` snapshot (balances, positions with `pct_of_portfolio`) in every run's context, because the agent skipped `get_positions` and acted on remembered holdings; a `BacktestError` while building it degrades to a `balance_error`/`positions_error` key rather than skipping the tick (it would never reach the agent-error counter).
- **Backtests simulate trailing stops** (`fills.evaluate_trailing_stop`): `BacktestBroker` keeps each `TRAIL` order's high/low-water mark in `_PendingOrder.trail_reference`, seeded with the latest close at submission, and tests the level from the previous bars *before* a bar's own high may raise it (ties against the trader). `evaluate_fill` still refuses `TRAIL`.
- **Yahoo bars: the download is `auto_adjust=False, actions=True`, run through the download date.** `YahooBacktestData` (and paper/live `YahooDailyBars`) downloads raw bars up to today plus one day, because Yahoo adjusts every price for every split up to the date a download ends, so the `Stock Splits` rows must cover splits after the window; `YahooBacktestData` then trims each backtest frame to the requested window by session date (`YahooDailyBars` keeps everything it downloaded). The download date is never a decision cutoff (no wall-clock cutoffs in data tools): `bars()` still serves only rows up to its cutoff. `parse_yahoo_frame` rebuilds `open/high/low/close/volume` with yfinance's own `auto_adjust` arithmetic (`ratio = Adj Close / Close`; pinned by `scripts/tests/smoke_traded_prices.py` against `yfinance.utils.auto_adjust` on the same download, exact), and adds `traded_close` / `traded_volume`: the split-adjusted `Close` times, and the `Volume` divided by, every LATER split ratio, i.e. what the stock really printed then. Only the traded columns feed the `min_price` / `min_dollar_volume` filters (`strategies/common/CLAUDE.md`). Two separate Yahoo requests do not return identical adjusted values (up to about 3e-4 between back-to-back downloads), so never compare a rebuild with another request at tight tolerance.
- **`uv run regime recompute` rewrites a run's `Regime` line in `indicators.parquet`; `backtest.log` keeps the old regime lines.** It replaces only the `Regime` rows (one per session with a reading, at the run's existing time of day, else 08:30 New York) and keeps every other line. The first rewrite copies the original to `indicators.pre-vix-regime.parquet` (atomic copy through a `.tmp`, never overwritten, so a second run keeps the first backup; restore by copying it back). A run that had no `indicators.parquet` gets an empty marker `indicators.pre-vix-regime.none` instead, so a later run never backs up our own file as if it were the original (restore = delete `indicators.parquet`). A run that raises (corrupt file) is reported as skipped and left as it was. The log text is not touched, so a recomputed run's `backtest.log` regime lines can disagree with its chart. `--dry-run` writes nothing.

# agents/ -- LangChain agents and their tools

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `agents/` -- LangChain agent creation/execution (lumibot's `strategy.agents`): `config.py` (**pure**: `LLMCredentials.from_env` (`LLM_BASE_URL` is normalized -- a pasted `.../v1/chat/completions` becomes `.../v1`; `LLM_API_KEY` is optional and defaults to a placeholder), mirrors `AlpacaCredentials`), `results.py` (**pure**: `AgentRunResult`/ `ToolCallRecord`, and a duck-typed parser from a LangChain message list), `manager.py` (`AgentManager`/`AgentHandle`, the only place that imports `langchain`/`langchain_openai`, and only inside method bodies), `telemetry.py` (**pure**: `CallRecord` per model call, `usage_from_message`, `summarize`), `stats_store.py` (`LLMStatsStore`, the only code writing `llm_stats.sqlite`). No builtin tools, no MCP/skills: the caller passes `tools=[...]` explicitly (e.g. `memory_tools(self.memory)`).
- `agents/tools/` -- LangChain tool factories for a trading agent. `trading.py`/`account.py`/`market_data.py`/`indicators.py` wrap `Strategy` methods; `prebuilt.py`'s `PrebuiltTools.all(strategy)` bundles those four plus `memory_tools` in one call. `common.py` (`only(tools, names)`: the subset of a tool list an agent's prompt describes, exported from the package) and `news.py`/`macro.py`/`fundamentals.py` are wired in explicitly (not part of `PrebuiltTools.all()`): news (via the broker's `NewsProvider`, `Broker.news_provider()`), FRED macro series (`fredapi`, lazy import), and SEC EDGAR fundamentals (`fundamentals/`). Every tool factory takes `strategy`, not a raw client, so research tools can gate on `strategy.clock.now()`.

## Gotchas

- **Research agent tools (news/macro/fundamentals) gate on `strategy.clock.now()`, not the price-bar chokepoint.** `BacktestDataSource.bars()` is the no-look-ahead gate for prices; nothing enforces the equivalent for news, FRED series or SEC filings. Each of `agents/tools/news.py`, `macro.py` and `fundamentals.py` takes the `Strategy` (not a raw client) specifically so it can pass `strategy.clock.now()` as an explicit `end`/`realtime_end`/`as_of` cutoff to its provider. A new research tool that skips this leaks future information into backtests exactly like a data tool that calls `datetime.now()` would. **All three work in every mode.** `macro_tools`/`fundamentals_tools` call FRED/SEC directly. `news_tools` goes through the broker-agnostic `NewsProvider` seam (`brokers/news.py`): `Broker.news_provider()` returns `None` by default; `AlpacaBroker` returns its `AlpacaNewsProvider` (`brokers/alpaca/news.py`); `BacktestBroker(news_source=...)` takes an injected provider, defaulting lazily to an Alpaca provider built from `AlpacaCredentials.from_env()` (`Strategy.run_backtesting(news_source=...)` mirrors `data_source=`). A future broker (e.g. IBKR) implements `news_provider()` itself. The clock gate stays in the tool, never in a provider. Article payloads are token-capped: `parse_news` truncates content at 6000 chars and `search_news` clamps `limit` to 5 when `include_content=True`.
- **Agent telemetry is opt-out in backtests, opt-in otherwise.** `run_backtesting(agent_telemetry=True)` is the default; paper/live need the class attribute `Strategy.agent_telemetry = True`. When on, `AgentManager.enable_telemetry` (called by the lazy `strategy.agents` property, so it precedes every `create()`) adds a `wrap_model_call` middleware that records each model call (tokens, latency, requested tool calls) into `memory/<strategy>/<mode>/llm_stats.sqlite` -- its own file so it can be deleted apart from `memory.sqlite` -- and per-agent totals into `settings.json["agents"]` (only if an agent ran; strategies without agents get neither). Same wipe rule as memory: deleted at the first `strategy.agents` access of a backtest, never in paper/live, where rows accumulate across restarts. Rows carry `run_id` (the run directory name, `Strategy.run_id`, set by the runners); the dashboard's `load_agent_calls` filters on it and reads the file read-only, so after a newer backtest only the latest run has per-call rows (its `settings.json` totals survive regardless). Telemetry is observational: a store failure logs a warning and never breaks the agent run. Latency is real `perf_counter` time, but each row's `ts` is `strategy.clock.now()`, so a backtest logs simulated time. Unreported token usage is `None` (shown as "—"), never `0`.
- **`agents/` defers every LangChain import to inside method bodies** (never at module level), mirroring `core/indicators.py`'s deferred `pandas_ta_classic` import -- a strategy that never calls `self.agents.create(...)` never pays for LangChain in memory. `AgentManager` doesn't know `Strategy` either; it takes a `credentials_source` callable (`LLMCredentials.from_env`).
- **Every agent gets a tool-call-repair `wrap_model_call` middleware, unconditionally** (`AgentManager._tool_call_repair_middleware`, first/outermost in `create()`'s middleware list, ahead of telemetry). A local model under long context sometimes writes out what should have been its next tool call as plain JSON text in the message content -- `{"name": ..., "arguments": {...}}`, sometimes with a trailing `</tool_call>` tag or stray `}` -- instead of using the API's real tool-calling channel; LangChain treats that as the final answer and never executes it, silently losing the call. The middleware parses that shape with `_parse_pseudo_tool_call` (`json.JSONDecoder.raw_decode` from the first `{`, so trailing junk doesn't block it) and, only when `name` matches a tool this agent actually has, rewrites the response into a real tool call before the graph continues. For a GLM model only (`_is_glm_model`: "glm" in the resolved chat model's `model_name`), it also parses GLM's own leaked template, `name<arg_key>k</arg_key><arg_value>v</arg_value>...</tool_call>` (`_parse_glm_tool_call`: the name must sit right before the first `<arg_key>`, values stay strings for the tool schema to coerce); other models (e.g. Qwen) never get that parser. Being outermost means telemetry still records what the model literally produced (0 requested tool calls), while the repaired message is what actually runs. `agent_news_binary.py`'s `_decision_was_recorded` warning stays as a defense-in-depth backstop for whatever malformed shape this doesn't catch -- including the case it structurally can't reach: the model placing a real trade via `submit_order` and then just writing a prose summary, skipping `remember_decision` entirely (nothing to repair -- no call was attempted). `on_trading_iteration` handles that one with a single corrective follow-up turn (`NewsBinaryStrategy._run_agent`/`_log_agent_result`), reusing the same `run_id` (`AgentHandle.run(..., run_id=...)`) so the retry stays part of the same logical run -- the news-grounding gate (`grounding.py`) doesn't need it to re-ground itself with another `search_news` call, and per-run memory dedup still treats the pair as one run. The retry is a fresh invocation whose first output is forced to be `remember_decision` (no room to reason, no turn-1 tool results), so `_build_retry_prompt` hands it what it needs: the orders the framework saw accepted (`submit_order` results without `"error"` -- the model has narrated trades it never submitted, so its prose is explicitly not proof), the tail of its own reply (capped at `RETRY_REPLY_MAX_CHARS`; long echoes preceded boilerplate loops), and a fixed `Regime: / Trades: / Reason:` template that keeps the `PENDING bearish flip:` prefix the hysteresis reads. The framework still never writes the decision itself. If the retry also fails (or itself raises `AgentError`), it is not retried again -- a second warning/error is logged and the run ends.
- **`AgentRunResult.tool_calls[i].result` is a string, not the tool's return value.** LangChain always stringifies (JSON-encodes) a tool's return value into `ToolMessage.content` before it reaches agent code, so the original Python object (e.g. a memory tool's `{id, kind, status}` dict) isn't recoverable there -- read it from the tool's own return value directly if you need it as data, not from the agent's result.
- **`Strategy.agents.create(..., timeout_seconds=None)` (the default) means no request timeout at all.** Deliberate: this framework targets slow, reasoning-capable local models that can legitimately take minutes per call, and a framework-imposed default would silently break that use case. The cost: per "Strategy code runs on one thread" in the root `CLAUDE.md`, a hung or OOM'd local LLM server blocks `on_trading_iteration()` -- and therefore order-event hook dispatch -- indefinitely. Pass an explicit `timeout_seconds` if your deployment needs one.
- **`agents.create(temperature=None, exempt_tools=None)` and `AgentHandle.run(tool_budget=None)` are opt-in.** `temperature=None` sends nothing (the server default applies); the telemetry summary records each agent's temperature. A per-run `tool_budget` is enforced by a `wrap_tool_call` middleware installed on every agent (a no-op without a budget): past the budget every tool but `exempt_tools` returns `{"error": "tool budget of N calls spent; <tool> was not run. ..."}` without running. The message is built only from the caller's own tool names.

# strategies/bull_bear/ -- bull vs bear debate

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `bull_bear/` (`BullBearStrategy` in `agent_bull_bear.py`, registered as `"bull_bear"`): lumibot's bull vs bear debate over cross_momentum's ranking, once a week (Tuesday 12:00 ET, `sleeptime = "1D"`, `BullBearParams.rebalance_weekday` = 1: every other session returns at once; a Tuesday whose review completed is not run again after a restart, unlike cross_momentum). Code ranks the universe with `strategies/common/scoring.py` and cross_momentum's own `CONFIG` (never duplicated) and builds the candidates (`debate_set.py`): the top `candidate_count` (15) plus the holdings ranked up to `retention_rank` (35), minus the stocks in their re-entry cooldown (`max_volatility` gates new entries only: the pipeline scores a holding with a copy of `CONFIG` that lifts it, so `scoring.py`/cross_momentum are untouched; a holding ranked worse, unranked or still in cooldown is a forced exit, sold by code, never shown to the agents, and logged as a warning (`forced exit: <symbol> (<reason>)`) just before its sell order is sent: not when the review is abandoned before execution, since nothing is sold then). The fact sheet (`fact_sheet.py`) has NO `held` or `weight_pct`: no agent is told what is held. Four agents hand over through submit tools validated by `HandoffRecorder` (`handoff.py`: `submit_note`, `submit_bull_case`, `submit_bear_case`, `submit_verdicts`; no `from __future__ import annotations`): a researcher run PER STOCK (`search_news` when `research_news` is on, plus the SEC `get_income_statement` (with cash flow and free cash flow) and `get_balance_sheet` (total debt), each value with its `prior_year`; `research_tool_budget` 3 with `submit_note` exempt; a failed run gives that stock the note "research unavailable"), then the bull and the bear, independently and from the same evidence, with no research tool (every stock rated low/medium/high; the bear names a concern, rates high only for a concrete named risk, may use `momentum_exhaustion` only for a reversal already under way (a negative one-month return and `drawdown_from_52w_high_pct` of -15 or below), and may not rate high a news event the price already reacted to (`return_1w_pct`) without naming its lasting consequence), then the judge: `in` or `out`, with a reason, on EVERY candidate, at most `max_book_size` (10) `in`, no veto cap; it sees its `previous_verdict` on a stock it judged before and must give `what_changed` to flip it (the submission is rejected otherwise), `recent_verdicts` (every `out` verdict of the last `feedback_reviews` (4) reviews that still has a price, with the stock's return since against that day's `in` stocks and its reason cut to 150 characters: the "then" close is the last session before the review's date in TODAY's loaded series (`DailySeries.dates`, `DailySeries.close_before`), the same adjustment basis as the latest close, so a split in paper/live (Yahoo bars are re-downloaded adjusted at every review) shows no fake return; the close stored with the verdict is the fallback; no price after `clock.now()`), and has `search_memory` and `remember_lesson` (`strategy.memory`, wiped at the start of every backtest; `judge_memory_budget` 6, `submit_verdicts` exempt). Code builds the book (`book.build_book`: every `in` stock, in rank order; no held-first rule), sizes it by inverse volatility within [4%, 20%] summing to `min(98%, n x 20%)` (`sizing.capped_inverse_volatility`; below 5 stocks the rest is parked in SHV, zero `in` parks everything but the cash buffer) and rebalances through `strategies/common/rebalancer.py`'s `Rebalancer`. A holding the judge puts out is sold and starts a cooldown of `reentry_cooldown_reviews` (4) completed reviews (`cooldown.advance_cooldowns`). No overlays. A bull, bear or judge with no valid submission after the forced retry (`ReviewPipeline._run_stage`: a run that submits nothing valid gets ONE more run with the submit tool forced; the warning for a run that ended without calling it names how it ended -- `finish_reason`, total and reasoning tokens, where the model reports them, a `length` stop with every token spent on reasoning being a spent token window; the `submission rejected` warning carries the same detail, since a run can hit the window right after a rejection; each agent has its own submit tool as `final_tools`, so a recorded submission ends the run with no closing model turn; the researcher and the judge are created with `compact_history=True` (history summarized at 80% of `LLM_MAX_INPUT_TOKENS`, which `initialize` therefore requires: a missing one is a `FatalStrategyError`; once a judge run is compacted, its `memory` record in `reviews.jsonl` counts only the memory calls kept) -- and the INFO lines `[<agent>] retrying with <tool> forced` and `[<agent>] forced retry recorded <tool>` show the retry and that it landed (the retry is a fresh run, so `retry_prompt` repeats the stage's task, which carries the symbol and the character cap, and, for the researcher, says its research is gone: the note rests on the fact sheet alone and must say that no news or filings were checked, never that none were found); a retry that fails too logs its own warning and abandons the review), unusable data (`market_data.YahooBars`: one Yahoo batch in paper/live, fetched again after 60 s and 180 s; `GateBars` in backtests), or no candidate at all abandons the review with NO order, forced exits included, and stores nothing but the streak; a `BrokerError`/`BacktestError` abandons it too (stage `broker` before the rebalancer starts: no order was sent; stage `execution` during it: orders may already be out, logged in `reviews.jsonl` with the judge's verdicts, the book, the targets and the orders placed so far). An abandoned review stores only the streak, except at the `execution` stage, where the judge has decided and orders may be out: its verdicts and a cooldown for each of its sells actually placed (`cooldowns_started` in that log line lists those, none when no sell went out) are stored, running cooldowns are not counted down, no `history` entry is added and the day stays open, so a stock sold that week is not bought back by the next review. A backtest raises `FatalStrategyError` at 3 abandoned in a row (paper/live log and carry on). State in `data/bull_bear_state_<mode>.json` (`StateStore`, `STATE_VERSION` 2: last completed review date, abandoned streak, the judge's latest verdict per stock, the cooldowns, the last `feedback_reviews` reviews' verdicts with their closes; a version-1 file (picker or veto judge) keeps its review date and streak and loads the rest empty, so a completed Tuesday is not reviewed again; any other version or invalid content loads empty with a warning; wiped by `initialize` in backtests only). `ReviewLog` appends one line per review (forced exits included) to `reviews.jsonl` in the run directory: `verdicts` (each with `what_changed` and `previous_verdict`), `verdict_counts`, `book`, `targets`, `cooldowns_active`, `cooldowns_started`, `recent_verdicts`, `memory` (calls and lessons); `dashboard/reviews_reader.py` reads `debate_set[].held`, `forced_exits`, `targets` and `orders` from `reviews.jsonl`, so those keys are kept. `research_news` (default on) is mirrored into `strategy.parameters`, so `settings.json` tells a news-off run apart; the news-off comparison run is made by setting `BullBearParams.research_news` to False (the strategy factory passes no `settings`, so the default in `parameters.py` is the switch: there is no command-line option). `AgentHandle.run` wraps every exception, `ConfigurationError` included, as `AgentError`, so a misconfiguration surfacing DURING a review costs only that stock's note ("research unavailable"); the real misconfigurations (news provider when `research_news` is on, SEC user agent, `LLM_MODEL`) are caught at `initialize`.

- `bull_bear/batch/` (run by hand over finished runs; the strategy never imports it): `agent_scores.py` (**pure**: `forward_returns` from the open of the first session after each review, the fill, to the open 5 and 20 sessions later, with the excess over that review's candidate mean; a candidate without an open, or a review the calendar does not reach back to, is dropped and counted, and an exit past the last session is counted apart as immature; `score_agents`: the bull's high - low conviction, the bear's low - high risk with a concern breakdown, the judge's in - out (a picker record's `picks` are in, the rest of its debate set out), each spread computed per review and averaged, with a t-stat across reviews, Newey-West with 3 lags at 20 sessions; abandoned reviews count for nothing) and `scores_cli.py` (`uv run bull-bear-scores <run_dir>...`: reads `reviews.jsonl` itself, never the dashboard's reader, fetches opens through `YahooDailyBars` with SPY as the calendar, prints runs side by side; exit 2 without `reviews.jsonl`, 1 on a Yahoo failure).

## Gotchas

- **bull_bear fails fast without a news source (unless `research_news` is off), and its sectors are not point-in-time.** `BullBearStrategy.initialize` calls `_require_news_provider` when `research_news` is on (`broker.news_provider()` must exist) and turns any `ConfigurationError` (no news provider, no model, missing `SEC_EDGAR_USER_AGENT`) into `FatalStrategyError`, in EVERY mode: `ALPACA_NEWS_*` is required for paper/live and backtests alike while `research_news` is on, stricter than bill_ackman, whose news tool only fails when called (a backtest builds its Alpaca provider lazily, so without the check every note of the run would be research-free). The fact sheet's sector comes from yfinance live, even in a backtest (`strategies/common/sector_provider.py`, cached per run, `"UNKNOWN"` on a failure): the agents see today's sector, a known look-ahead on a label, not a price. Paper/live read daily bars from Yahoo through `market_data.YahooBars` (cross_momentum's reasoning: IEX volume would empty the $20M filter); a backtest reads the gate (`Strategy.get_historical_prices`) and `run_backtesting` preloads the universe, SHV and SPY in one Yahoo download. A forced exit is sold by `Rebalancer` only once the review reaches execution: a review abandoned before that sells nothing, so a data outage never liquidates the book.
- **Every agent's turns are capped and its runaway thinking turned off.** All four agents get `BullBearParams.max_output_tokens` (12288, recorded in `settings.json`: in the 10-17 run every call that worked used at most 11k output tokens, every one that thought the 32k window full 19k+; see `agents/output_cap.py`) and `thinking.py`'s `thinking_guards`. A turn stopped at the cap with no tool call is asked again with Qwen's thinking off (`extra_body.chat_template_kwargs.enable_thinking=False`, verified on vLLM 0.30) and the submit tool forced; the turn after a rejected submission runs that way from the start. Both act inside the run, so the research is kept (the pipeline's forced retry is a fresh run). A run ends with nothing recorded at `MAX_REJECTIONS` (3) rejected submissions -- forced and without thinking, a valid submission is otherwise the only way out, and compaction would let it loop up to LangGraph's 9,999 steps; `_run_stage`'s forced retry, then abandonment, take over. The rejection guard must stay outermost (`thinking_guards` returns them in order), or the length guard asks a thinking-off correction again.
- **A note is asked for at `note_max_chars` (500) but refused only above `note_hard_max_chars` (600).** A model cannot count characters: in the 10-19 run 25 notes came back 1-20% over 500, and the correction, forced and without thinking, re-sent the same text (504, 504, 504), so three rejections ended the run and the pipeline's forced retry, a fresh run, wrote the note from the fact sheet alone: the news and filings the first run found were lost over a few characters. The prompt (`researcher_task`) and the retry prompt keep saying 500; only the recorder's error says 600. `thinking.py`'s warnings carry the tool's rejection reason (cut at 300 characters; it names the stock): they are logged while the run is going, before the pipeline logs the run's dump and note, so without it a warning looks like it belongs to the stock logged just above it.

# strategies/bull_bear/ -- bull vs bear debate

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `bull_bear/` (`BullBearStrategy` in `agent_bull_bear.py`, registered as `"bull_bear"`): lumibot's bull vs bear debate over cross_momentum's ranking, once a week (Tuesday 12:00 ET, `sleeptime = "1D"`, `BullBearParams.rebalance_weekday` = 1: every other session returns at once; a Tuesday whose review completed is not run again after a restart, unlike cross_momentum). Code ranks the universe with `strategies/common/scoring.py` and cross_momentum's own `CONFIG` (never duplicated), debates the top 15 plus the holdings ranked 16-35 (`debate_set.py`; a holding ranked worse or unranked is a forced exit, sold by code, never shown to the agents, and logged as a warning (`forced exit: <symbol> (<reason>)`) just before its sell order is sent: not when the review is abandoned, since nothing is sold then) and builds the fact sheet (`fact_sheet.py`). Four agents hand over through submit tools validated by `HandoffRecorder` (`handoff.py`: `submit_note`, `submit_bull_case`, `submit_bear_case`, `submit_picks`; no `from __future__ import annotations`): a researcher run PER STOCK (news + SEC income statement and balance sheet, `research_tool_budget` 3 with `submit_note` exempt; a failed run gives that stock the note "research unavailable"), then the bull and the bear, independently and from the same evidence, with no research tool (every stock rated low/medium/high; the bear names a concern), then the judge (5-10 picks; `drops` must name exactly the held debate stocks not picked). Code sizes the picks by inverse volatility within [4%, 20%] summing to 98% (`sizing.capped_inverse_volatility`, a bisection, so both bounds hold) and rebalances through `strategies/common/rebalancer.py`'s `Rebalancer`. No overlays. A bull, bear or judge with no valid submission after the forced retry, unusable data (`market_data.YahooBars`: one Yahoo batch in paper/live, fetched again after 60 s and 180 s; `GateBars` in backtests), or a debate set under `min_picks` abandons the review with NO order, forced exits included; a `BrokerError`/`BacktestError` abandons it too (stage `broker` before the rebalancer starts: no order was sent; stage `execution` during it: orders may already be out, logged in `reviews.jsonl` with the judge's picks, drops and targets); a backtest raises `FatalStrategyError` at 3 abandoned in a row (paper/live log and carry on). State in `data/bull_bear_state_<mode>.json` (`StateStore`: last completed review date, abandoned streak, last picks, kept for the log and not shown to the agents; wiped by `initialize` in backtests only), `ReviewLog` appends one line per review (forced exits included) to `reviews.jsonl` in the run directory. `AgentHandle.run` wraps every exception, `ConfigurationError` included, as `AgentError`, so a misconfiguration surfacing DURING a review costs only that stock's note ("research unavailable"); the real misconfigurations (news provider, SEC user agent, `LLM_MODEL`) are caught at `initialize`.

## Gotchas

- **bull_bear fails fast without a news source, and its sectors are not point-in-time.** `BullBearStrategy.initialize` calls `_require_news_provider` (`broker.news_provider()` must exist) and turns any `ConfigurationError` (no news provider, no model, missing `SEC_EDGAR_USER_AGENT`) into `FatalStrategyError`, in EVERY mode: `ALPACA_NEWS_*` is required for paper/live and backtests alike, stricter than bill_ackman, whose news tool only fails when called (a backtest builds its Alpaca provider lazily, so without the check every note of the run would be research-free). The fact sheet's sector comes from yfinance live, even in a backtest (`strategies/common/sector_provider.py`, cached per run, `"UNKNOWN"` on a failure): the agents see today's sector, a known look-ahead on a label, not a price. Paper/live read daily bars from Yahoo through `market_data.YahooBars` (cross_momentum's reasoning: IEX volume would empty the $20M filter); a backtest reads the gate (`Strategy.get_historical_prices`) and `run_backtesting` preloads the universe, SHV and SPY in one Yahoo download. A forced exit is sold by `Rebalancer` only when the review completes: an abandoned review sells nothing, so a data outage never liquidates the book.

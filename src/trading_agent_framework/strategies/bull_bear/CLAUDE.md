# strategies/bull_bear/ -- bull vs bear debate

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `bull_bear/` (`BullBearStrategy` in `agent_bull_bear.py`, registered as `"bull_bear"`): lumibot's bull vs bear debate over cross_momentum's ranking, once a week (Tuesday 12:00 ET, `sleeptime = "1D"`, `BullBearParams.rebalance_weekday` = 1: every other session returns at once; a Tuesday whose review completed is not run again after a restart, unlike cross_momentum). Code ranks the universe with `strategies/common/scoring.py` and cross_momentum's own `CONFIG` (never duplicated) and builds the candidates (`debate_set.py`): the top `candidate_count` (15) plus the holdings ranked up to `retention_rank` (35), minus the stocks in their re-entry cooldown (`max_volatility` gates new entries only: the pipeline scores a holding with a copy of `CONFIG` that lifts it, so `scoring.py`/cross_momentum are untouched; a holding ranked worse, unranked or still in cooldown is a forced exit, sold by code, never shown to the agents, and logged as a warning (`forced exit: <symbol> (<reason>)`) just before its sell order is sent: not when the review is abandoned before execution, since nothing is sold then). The fact sheet (`fact_sheet.py`) has NO `held` or `weight_pct`: no agent is told what is held. Four agents hand over through submit tools validated by `HandoffRecorder` (`handoff.py`: `submit_note`, `submit_bull_case`, `submit_bear_case`, `submit_verdicts`; no `from __future__ import annotations`): a researcher run PER STOCK (`search_news` when `research_news` is on, plus the SEC `get_income_statement` (with cash flow and free cash flow) and `get_balance_sheet` (total debt), each value with its `prior_year`; `research_tool_budget` 3 with `submit_note` exempt; a failed run gives that stock the note "research unavailable"), then the bull and the bear, independently and from the same evidence, with no research tool (every stock rated low/medium/high; the bear names a concern, rates high only for a concrete named risk, may use `momentum_exhaustion` only for a reversal already under way (a negative one-month return and `drawdown_from_52w_high_pct` of -15 or below), and may not rate high a news event the price already reacted to (`return_1w_pct`) without naming its lasting consequence), then the judge: `in` or `out`, with a reason, on EVERY candidate, at most `max_book_size` (10) `in`, no veto cap; it sees its `previous_verdict` on a stock it judged before and must give `what_changed` to flip it (the submission is rejected otherwise), `recent_verdicts` (every `out` verdict of the last `feedback_reviews` (4) reviews with the stock's return since against that day's `in` stocks, from the close stored with each verdict and the latest loaded close: no price after `clock.now()`), and has `search_memory` and `remember_lesson` (`strategy.memory`, wiped at the start of every backtest; `judge_memory_budget` 6, `submit_verdicts` exempt). Code builds the book (`book.build_book`: every `in` stock, in rank order; no held-first rule), sizes it by inverse volatility within [4%, 20%] summing to `min(98%, n x 20%)` (`sizing.capped_inverse_volatility`; below 5 stocks the rest is parked in SHV, zero `in` parks everything) and rebalances through `strategies/common/rebalancer.py`'s `Rebalancer`. A holding the judge puts out is sold and starts a cooldown of `reentry_cooldown_reviews` (4) completed reviews (`cooldown.advance_cooldowns`). No overlays. A bull, bear or judge with no valid submission after the forced retry, unusable data (`market_data.YahooBars`: one Yahoo batch in paper/live, fetched again after 60 s and 180 s; `GateBars` in backtests), or no candidate at all abandons the review with NO order, forced exits included, and changes no verdict, cooldown or history; a `BrokerError`/`BacktestError` abandons it too (stage `broker` before the rebalancer starts: no order was sent; stage `execution` during it: orders may already be out, logged in `reviews.jsonl` with the judge's verdicts, the book, the targets and the orders placed so far). No abandoned review, whatever its stage, stores a verdict, a cooldown or a history entry, so after an `execution` abandonment a stock the judge sold that week is not in cooldown and may be re-entered the next week; `cooldowns_started` still lists it in that abandoned log line. A backtest raises `FatalStrategyError` at 3 abandoned in a row (paper/live log and carry on). State in `data/bull_bear_state_<mode>.json` (`StateStore`, `STATE_VERSION` 2: last completed review date, abandoned streak, the judge's latest verdict per stock, the cooldowns, the last `feedback_reviews` reviews' verdicts with their closes; a version-1 file (picker or veto judge) loads as an empty state; wiped by `initialize` in backtests only). `ReviewLog` appends one line per review (forced exits included) to `reviews.jsonl` in the run directory: `verdicts` (each with `what_changed` and `previous_verdict`), `verdict_counts`, `book`, `targets`, `cooldowns_active`, `cooldowns_started`, `recent_verdicts`, `memory` (calls and lessons). `research_news` (default on) is mirrored into `strategy.parameters`, so `settings.json` tells a news-off run apart; the news-off comparison run is made by setting `BullBearParams.research_news` to False (the strategy factory passes no `settings`, so the default in `parameters.py` is the switch: there is no command-line option). `AgentHandle.run` wraps every exception, `ConfigurationError` included, as `AgentError`, so a misconfiguration surfacing DURING a review costs only that stock's note ("research unavailable"); the real misconfigurations (news provider when `research_news` is on, SEC user agent, `LLM_MODEL`) are caught at `initialize`.

## Gotchas

- **bull_bear fails fast without a news source (unless `research_news` is off), and its sectors are not point-in-time.** `BullBearStrategy.initialize` calls `_require_news_provider` when `research_news` is on (`broker.news_provider()` must exist) and turns any `ConfigurationError` (no news provider, no model, missing `SEC_EDGAR_USER_AGENT`) into `FatalStrategyError`, in EVERY mode: `ALPACA_NEWS_*` is required for paper/live and backtests alike while `research_news` is on, stricter than bill_ackman, whose news tool only fails when called (a backtest builds its Alpaca provider lazily, so without the check every note of the run would be research-free). The fact sheet's sector comes from yfinance live, even in a backtest (`strategies/common/sector_provider.py`, cached per run, `"UNKNOWN"` on a failure): the agents see today's sector, a known look-ahead on a label, not a price. Paper/live read daily bars from Yahoo through `market_data.YahooBars` (cross_momentum's reasoning: IEX volume would empty the $20M filter); a backtest reads the gate (`Strategy.get_historical_prices`) and `run_backtesting` preloads the universe, SHV and SPY in one Yahoo download. A forced exit is sold by `Rebalancer` only once the review reaches execution: a review abandoned before that sells nothing, so a data outage never liquidates the book.

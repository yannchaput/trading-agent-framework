## Architecture

- `news_builtin/` (`NewsBinaryStrategy` in `agent_news_binary.py`, registered as `"news_binary"` in `utils/strategy_factory.py`: an LLM agent built from `PrebuiltTools.all(self)` + `news_tools(self)`; system prompt is inline in `agent_news_binary.py`, grounding logic in `grounding.py`).

## Gotchas

- **`news_binary`'s grounding gate (`grounding.py`) requires that `search_news` was called with `include_content=True` this run -- but not that it returned any content.** It has been through three iterations. (1) Required only that some `search_news` call succeeded (headline scan alone grounded the run) -- the local LLM was observed deciding straight off headlines without ever attempting to read a specific article. (2) Required an `include_content=True` call to also return an article with non-empty `content` -- this backfired: some trading days' news for the queried symbols is nothing but terse Benzinga data-print wires that never carry a body on the provider's side no matter how the search window is narrowed, so the requirement was sometimes impossible to satisfy; the model retried different articles as its own refusal message instructed, all refused, sometimes 100+ tool calls in one run, until it exhausted its turn/token budget with no decision recorded (the exact failure the tool-call-repair middleware and the retry-once mechanism below exist to catch the shape of, neither of which can produce a decision that was never attempted) -- briefly "fixed" by dropping the `include_content=True` requirement entirely back to (1), which cured the deadlock but meant the agent never even attempted a content read (confirmed: 100% headline-only across a full backtest log). (3), the current form: grounds on the *attempt* -- `search_news` must be called with `include_content=True` (`_requested_full_content` binds args against the real signature via `inspect.signature`, so positional or keyword both count), but an empty-content response still grounds the run (no `_received_full_content` check). The prompt (step 3) mirrors this: the call is mandatory, but "if this call comes back with no content... proceed to decide using the headline alone" rather than keep searching for content that may not exist that day. glm-4.7-flash was independently observed re-deriving the rejected (2) rule anyway -- across separate paper and backtest runs it wrote "the gating rule requires a full-text/body-grounded article", something never in this codebase, into `remember_decision` (which then re-surfaced through `search_memory` in later runs). The refusal message's old wording, "grounded in a specific article", was the likely trigger: read literally it does sound like the article's substance is required, not just the attempt. The refusal now says outright that an empty result counts and that the call itself is what's required.

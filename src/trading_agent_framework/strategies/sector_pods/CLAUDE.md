# strategies/sector_pods/ -- five sector pods, a risk manager and a portfolio manager

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`. Design: `docs/superpowers/specs/2026-11-09-sector-pods-design.md`; plan: `docs/superpowers/plans/2026-11-09-sector-pods.md`. Inspired by lumibot's Citadel sector pods example; not affiliated with Citadel.

## Architecture

`SectorPodsStrategy` (`agent_sector_pods.py`, registered as `Strategies.SECTOR_PODS`, `"sector_pods"`) rebalances 27 sector ETFs once a week (Tuesday 12:00 ET, `sleeptime = "1D"`; every other session returns at once, and a Tuesday already completed is not run again after a restart). The weekly flow is one LangGraph graph (`graph.py`, `build_graph`) built once in `initialize`, over the plumbing of `agents/graph.py` (`AgentNode`, `merge_dicts`; the recorder is `agents/submit.py`'s `NodeRecorder`):

```
START -> load_previous -> market_facts -> tech_pod ---------\
                                      -> financials_pod ----\
                                      -> healthcare_pod -----> risk_manager -> portfolio_manager -> execute -> END
                                      -> energy_pod --------/
                                      -> consumer_pod ----/
```

Shared state `PodsState` (`TypedDict`); `pods` is merged across the parallel pods (`merge_dicts`) and `errors` is appended to, every other slot has one writer:

| Slot | Written by | Read by |
|---|---|---|
| `date`, `regime` (label), `holdings` (weights) | `market_facts` | pods (`date`, `regime`), risk, PM, `Execute` |
| `previous` (last completed week: `date`, `pods`, `risk`, `pm`) | `load_previous` | each pod (its own last view), risk (its own), PM (its own), `market_facts` (outcome) |
| `facts` (pod key -> symbol -> row) | `market_facts` | each pod (its own sleeve), risk, PM, validators |
| `stress` (`early_warning`, `regime_score`, `conditions`, `defensive_etfs`; null when unavailable) | `market_facts` | risk, PM, `Execute` |
| `outcome` | `market_facts` | PM |
| `pods` (pod key -> view or `UNAVAILABLE`) | the pod nodes | risk, PM, `Execute` |
| `risk` | `risk_manager` | PM, `Execute` |
| `pm` (`weights`, `overrides`, `summary`) | `portfolio_manager` | `Execute` |
| `errors` | any `AgentNode` that ended unavailable | the `reviews.jsonl` record |
| `orders`, `abandoned` | `Execute` | the strategy (`abandoned`), the log |

Agents hand over through submit tools (`handoff.py`, no `from __future__ import annotations`): `submit_pod_view` (an integer score -2..+2 and a reason for EVERY ETF the pod has facts for, plus `sector_view`), `submit_risk_review` (objections with symbols, kind (crowding, macro, drawdown, reversal, stress, other), severity, reason; none is fine; plus `summary`), `submit_target_weights` (a weight and reason per ETF, `overrides`, `summary`). Each is the agent's `final_tools` (the recorded call ends the run) and a `ToolBudget` exempt tool (not counted in the tool budget). Pods have `search_news` and the macro tools (`pod_tool_budget` 4), the risk manager has none, the PM has `search_memory` (`pm_memory_budget` 3) and `remember_lesson` (exempt from that budget, asked for at most once; `strategy.memory`). No agent can place an order. **Texts go through a length gate** (`agents/tools/text.py`, strategy-agnostic; `NodeRecorder(submit, validator, gate=LengthGate(max_submit_attempts, name=submit, log_tag="sector_pods"))`, built in `_node`, reset by `arm`). Every agent has the exempt core tool `count_characters` and its prompt (`count_step`) asks it to count every text before it submits. Each submit tool hands its `reason`s and its `sector_view` / `summary` / `overrides` to `handoff._submit`, which asks the gate: an over-long text (stated limits `reason_max_chars` 200, `summary_max_chars` 400, the only ones the prompts quote) is refused with `too long: <label> has <n> characters (limit <m>); ...` while fewer than `max_submit_attempts - 1` (default 3, so 2) LENGTH refusals have happened in the node run (a weight-cap or score refusal uses none; a forced retry shares them); then the submission is accepted (the first valid one wins: a later one is refused with `already recorded for this run`) and any text above the hard caps (`reason_hard_max_chars` 300, `summary_hard_max_chars` 700, never quoted) is cut at a sentence with `trim_text`, one WARNING per cut (`[sector_pods] submit_pod_view: reason for XLK trimmed from 341 to 287 characters (limit 300)`). The validators check the HARD caps, so a text the gate let through is never refused for length. `max_agent_steps` is 60 (a worst-case PM run: 3 searches, the lesson, 2 counts, 3 submits). Why: the models cannot count characters. Run 2026-11-16_085725 (107 weeks, trim only, caps 200/400) logged 726 trims: 48-79% of every `sector_view`, risk `summary`, PM `summary` and `overrides` lost their last sentence, 9-14% of the financials, consumer and risk reasons; raw lengths overshot the limit by up to 1.7x. Refusing without a count (run 2026-11-11_135417: 181 of 182 refusals were lengths, 9 loops in 11 weeks, 3 of them the PM, so 3 weeks without a book) looped, because a refused model guesses how much to cut. Spike (84 replayed runs of that backtest, qwen3.8-27b): refuse-once alone left 8 of 28 final submissions over the limit; with the counter 0 of 56, even when the first count was inflated x1.3 on purpose (20 of 20 over-limit counts were shortened and recounted). Design: `docs/superpowers/specs/2026-11-16-submit-length-gate-design.md`. Prompts: `prompts.py`; every threshold: `SectorPodsParams` (`params.py`, frozen, validated).

- **Pods and sleeves** (`pods.py`, the single table prompts and checks are built from): `tech_pod` (XLK XLC SMH IGV FDN), `financials_pod` (XLF KRE KIE IYR), `healthcare_pod` (XLV XBI IHI XPH IHF), `energy_pod` (XLE XOP OIH XLU XLB XME XLI ITA IYT), `consumer_pod` (XLY XLP XHB XRT) -- 27 ETFs in all (`ALL_SYMBOLS`). Unspent money parks in SHV (not a sleeve; the PM never sets it); the benchmark is SPY.
- **Keep or trim.** An ETF whose pod gave no view this week (pod unavailable, or the symbol dropped for lack of history) is "unresearched": the PM may keep it at up to its current weight or cut it, never raise it (`unresearched(state)` is shown to the PM; `check_weights` enforces it).
- **Caps, enforced twice** by the same function `handoff.check_weights`: 25% per ETF (`max_etf_weight`), 40% per pod (`max_pod_weight`), 98% in total (`1 - cash_buffer`), only the 27 ETFs, plus the keep-or-trim rule. Once in the PM's submit tool (a violation is returned to the model as `{"error": ...}` so it can fix it) and again in `Execute` (a hostile or malformed book abandons the week with `execution: <problem>` and no order). **Always invested.** The PM's weights set the MIX, not the size: after `check_weights` accepts them, `Execute` fills the book with `handoff.fill_book` to `1 - cash_buffer` (98%): the researched ETFs are scaled in proportion, an ETF over 25% is clipped and a pod over 40% is cut back (unresearched ETFs keep their weight and count toward their pod's cap), and what a cap cuts is spread in proportion over the ETFs still below theirs; the filled book is checked again by `check_weights`. When every researched ETF is at a cap the rest stays in SHV (`book filled from 40.0% to 50.0% invested (the caps hold it below 98.0%)`). Why: the PM held 53% invested on average (56% in the bullish weeks) in the 2-year run 2026-11-16_181406, and its own picks scaled to 98% would have made 15.6% CAGR against 10.2% as traded (SPY 19.1%): the cash, not the ETF selection, was most of the gap. No regime-based sizing, no switch: always invested was the user's call. Design: `docs/superpowers/specs/2026-11-17-sector-pods-always-invested-design.md`. The target is then built by `common/portfolio.target_portfolio` and traded by `common/rebalancer.Rebalancer`.
- **Market facts** (`facts.py`, `etf_facts`, percents rounded to 0.1): `return_{1w,1m,3m,6m}_pct` (5/21/63/126 sessions), `relative_{1m,3m}_pct` (ETF minus SPY, in points), `volatility_20d_pct` (annualized), `vs_200d_avg_pct` (last close against the mean of the last 200 closes). An ETF with fewer than `MIN_BARS` (201) closes gets no row and is dropped from its pod's facts. `outcome` scores last week's book against this week: `positions_1w_pct` (each weighted symbol's return), `invested_weight`, `portfolio_1w_pct` (the return on the WHOLE portfolio, sum of weight x return, so SHV and cash count 0), SPY's (`week_return_pct(spy_closes)`: only the 5-session return, so 6 closes are enough, with `etf_facts`' window and rounding), and per pod the mean 1-week return of its positively scored symbols minus its negatively scored ones. **Shortcut:** the window is "last 5 sessions", not the sessions since the previous review (a holiday week or an abandoned week makes it approximate). The regime is passed to the agents as a label (bullish / neutral / bearish / unknown) for context only; nothing in code trades on it. `stress` is the same reading in full plus the fast VIX-based `early_warning`, with `DEFENSIVE_ETFS` (`pods.py`: XLP, XLV, XLU) as the sleeves to tilt toward; only the risk manager and the PM see it, never the pods.
- **Failure handling.** `AgentNode` retries once with the submit tool forced (not after an `AgentLoopError`), else writes `UNAVAILABLE` plus an `errors` entry: a pod unavailable (its ETFs become unresearched), risk unavailable (the PM sees `risk: unavailable`), PM unavailable (`Execute` abandons the week: "the portfolio manager gave no book", no order). Data unavailable (`DataUnavailable` from the bars, or no ETF with enough history) sets `abandoned = "data: ..."`; every agent node then returns at once (`skip_if_abandoned`) and `Execute` records the week. A pod with no facts is not run. A `BrokerError`/`BacktestError` inside `Rebalancer.rebalance` abandons the week at stage `execution` (orders already sent are logged); so does a rebalance that sends NO accepted order although some ETF's target differs from its current weight by more than the rebalance band (`Execute._trades_due` with `Rebalancer.refused` above 0: the broker refused every order, `execution: no order was accepted`; a rebalance that sent no order and was refused none completes the week with a WARNING `the rebalancer sent no order although the book needs trades: nothing could be funded`, since the shared rebalancer now funds a buy by trimming overweight stocks and an unfundable one is not a failure of the week), otherwise the week would count as done and the next outcome would score a book that was never held; one escaping the graph (holdings read) is caught in `on_trading_iteration`, which bumps the streak and keeps last week's views. An abandoned week stores only `abandoned_streak + 1`; the day stays open. A backtest raises `FatalStrategyError` at `max_consecutive_abandoned` (3) abandoned weeks in a row; paper/live log and carry on.
- **Persistence.** `data/sector_pods_state_<mode>.json` (`StateStore(JsonStateStore)`, `STATE_VERSION` 1): `last_completed`, `abandoned_streak`, `previous` = the last COMPLETED week's `{date, pods, risk, pm}` (an abandoned week never replaces it). Wiped by `initialize` in backtests only (`fresh=`). `reviews.jsonl` (`RunLog`, run directory) gets one record per review that reached `Execute`, abandoned or not: `date`, `regime`, `stress`, `holdings`, `facts`, `outcome`, `pods`, `risk`, `pm` (what the PM submitted), `book` (the weights traded after `fill_book`, null when nothing was traded), `orders`, `errors`, `abandoned` (reason or null), `abandoned_streak`. Settings recorded in `settings.json`: `max_etf_weight`, `max_pod_weight`, `thinking_token_budget`, `max_output_tokens`.
- **Data.** Paper/live read daily bars from Yahoo (`YahooDailyBars` through `common/daily_bars.YahooBars`: retries after 60 s and 180 s, `min_yahoo_coverage` 0.9); a backtest reads the data-source gate (`GateBars`) and `run_backtesting` preloads the 27 ETFs, SHV and SPY. Default backtest window: `PredefinedWindow.MONTH_LATEST` (about 10 weekly reviews, a cheap first run; `SEMI_DECADE_LATEST` for the full history), warmup 300 days.

## Gotchas

- **Threads (LangGraph 1.2.16, verified, pinned by tests).** The five pods run in parallel on `ThreadPoolExecutor` worker threads; with `invoke()` and no `step_timeout` (which is how `on_trading_iteration` calls it) a superstep with a single node runs on the calling thread (inline only when `timeout is None and get_waiter is None`), so `load_previous`, `market_facts`, `risk_manager`, `portfolio_manager` and `Execute`/`Rebalancer` all run on the strategy thread (order code must, per the root rule). Pods may therefore only call read-only research tools (news, macro). Streaming modes (`messages`/`custom`), `subgraphs=True` or a `step_timeout` would send every node, order code included, to a worker thread: a future graph using them must keep `Execute` outside the graph.
- **Each pod gets its OWN news and macro tool instances** (`_graph_parts` calls `news_tools` and `macro_tools` per pod, and each pod has its own `NodeRecorder`). `news_tools` keeps a `RunMemo` that remembers only the latest run id, so one instance shared between pods would reset between pods (`macro_tools` has no memo); separate instances stay the rule. Both read the cutoff from `strategy.clock.now()` (`agents/CLAUDE.md`), so a backtest has no look-ahead.
- **The strategy logs its own order events.** `on_new_order`, `on_partially_filled_order` and `on_filled_order` write `new order: ...` / `order filled: sell 7.84 XLK @ $96.84 (id ...)` lines (same wording as bull_bear's, copied on purpose: the base `Strategy` hooks and the executor stay silent), so a paper/live run shows what each rebalance did.
- **`Rebalancer.rebalance` swallows per-order errors** (it logs them and goes on), so a refused order does not abandon the week; only a `BrokerError`/`BacktestError` that escapes it does, or `Execute`'s own check that at least one order was accepted when the book needed trades.
- **Run it on an account that holds only this strategy's positions.** `Rebalancer` sells every long position that is not in the target, and it reads the whole account: a position left by another strategy or a smoke test (say AAPL) is sold on the first rebalance, because the target holds only the 27 ETFs and SHV. The PM never sees such a position as sellable (`unresearched` ignores non-sector symbols).
- **Known gap: a held sleeve ETF whose quote fails at the holdings read shows weight 0.0**; if its pod is also unavailable that week, keep-or-trim then forces it to 0 (sold). It needs two failures at once.
- **Known gap: a week whose error escapes the graph** (holdings `BrokerError`, `BacktestError` from the bars gate) bumps `abandoned_streak` but writes no `reviews.jsonl` line.
- **Env:** `LLM_*`, `ALPACA_NEWS_*` and `FRED_API_KEY` (macro tool), plus broker keys in paper/live. `initialize` fails fast (`FatalStrategyError`) without a news provider, in every mode (`common/news.py`'s `require_news_provider`, shared with bull_bear). `LLM_MAX_INPUT_TOKENS` is NOT required (no agent uses `compact_history`).
- **Sectors and the sleeve are not point-in-time**: the 27 ETFs are today's list. XLC only starts in mid-2018, so earlier it has fewer than 201 bars and is dropped from the tech pod's facts (the pod still runs on the rest).
- **Regime is context only.** `strategy.regime` is shown to the agents as a label; using it in code would be a new design decision (root `CLAUDE.md`). `stress` is context too: the PM prompt asks for a tilt toward `defensive_etfs`, but `check_weights`, `fill_book` and the caps are unchanged and the book stays fully invested.

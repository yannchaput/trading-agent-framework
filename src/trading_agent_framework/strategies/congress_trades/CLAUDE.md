# strategies/congress_trades/ -- House Clerk disclosures

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `congress_trades/` (`CongressTradesStrategy`, registered as `"congress_trades"`): a researcher → portfolio manager → trader pipeline over one member's Clerk disclosures (`CongressParams.politician`, default Nancy Pelosi). `sleeptime = "1D"` and `iteration_start_time = 10:00`, but `CongressPipeline` acts only on a new filing. `congress/` (the Clerk disclosures layer, below) and `tools/congress.py` (`congress_research_tools(strategy, source)`: `list_filings` and `read_filing` for the researcher, lazy-exported from `tools/`), `handoff.py` (`submit_holdings`, `submit_target`, `submit_trade_report`, validated by `HandoffRecorder`, no `from __future__ import annotations`), `desk.py` (`TradeDesk`, the only order code: the trading agent's `place_order` / `check_orders`, `audit`), `state.py` (`StateStore`: `processed` DocIDs, holdings, target, `traded`, `pending_trade`, abandoned streak, in `data/congress_trades_state_<mode>.json`; `RunLog` writes `runs.jsonl`), `prompts.py`, `parameters.py`.
- `strategies/congress_trades/congress/` -- House Clerk financial disclosures for `congress_trades` (`__init__` exports `ClerkClient` and `CongressSource`). **Pure**: `ptr.py` (filing index -> `FilingRef` for types `P` = PTR and `O` = annual report only, exact member-name match, PTR rows -> `Transaction`, `strip_descriptions`, `parse_row_head`), `annual.py` (value-band table `VALUE_BANDS`, `tier_of`, Schedule A rows -> `AssetHolding`, `period_end`), `holdings.py` (`reconstruct` = the yearly report's assets plus every trade dated AFTER its Dec 31, as value intervals; `baseline_weights` = `tier_base ** tier`, capped, floored by dropping the lowest). `clerk_client.py` (`ClerkClient`, the only module allowed to import `httpx` and `pypdf` for the Clerk; text cached forever, a year's index refetched by the caller's clock) and `source.py` (`CongressSource.known(as_of)` = the newest readable yearly report plus the PTRs filed after its period end, all filed strictly before `as_of`'s market date; `new_since` = known DocIDs minus the processed ones).

## Gotchas

- **congress_trades keys every disclosure on its FILING date, strictly before today's market date.** Disclosures lag the trade by up to 45 days (the yearly report by months), so a trade-date key would look into the future in a backtest. `CongressSource.known` applies the rule and `congress_research_tools` applies it again to whatever a source returns. "What she owns today" = the newest readable yearly report (type `O`; its Year is the reporting year and the index of that year lists it, filed the next May) as value bands at its Dec 31, plus every PTR trade whose TRANSACTION date is after that Dec 31 (a trade dated on or before it is already inside the report; a PTR filed before the report but traded after the Dec 31 IS applied). Filing types `C` (candidate report) and `A` (amendment of any kind) are ignored on purpose. Estimates are intervals from bands and ranges, not shares, and options are ignored (long-only stocks), so much of her real exposure is not copied. **Real layouts (checked against her filed report and PTRs):** a Schedule A row is `<name> (<TICKER>) [ST] <owner SP|JT|DC> <value band wrapped over two lines> <income>`, the owner comes AFTER the tag, `L:` / `D:` description lines follow rows (`strip_descriptions` removes them), a value of `None` means sold out during the year, and the report's own Schedule B lists its year's trades as `[ST] SP <date> <side> <amount>` (neither is a holding); a PTR row is `<owner> <name> (<TICKER>) [ST] <side> <traded> <notified> <amount>`; the PDF folder is the index year. **Not yet seen in a real filing:** a Schedule A stock row with no owner code (assumed to be the filer's own) and a PTR `S (partial)` row, both covered only by synthetic tests.
- **congress_trades acts only on a new filing, and that is decided in code.** With no filing since the last COMPLETED run and no pending trade, no agent runs and no order is sent (a "nothing_new" line in `runs.jsonl`); `processed` is saved only when a run completes, so an abandoned run leaves the filings new. A trading stage that ends with orders still working (a daily backtest fills a market order on the next bar, so the 10:00 tick always finds them `working`) or a position off its target by more than the band stores a `pending_trade`: later ticks re-run ONLY the trading stage against the stored target (`max_trade_retries` = 3, a failed attempt still uses one), never re-send an order that is still open (the desk counts open orders; `Audit.in_flight`), and a new filing replaces it. A trader that sent orders but never reported them keeps the research and leaves a pending trade; with no order sent the whole run is abandoned. The trading agent HAS order tools, unlike the Ackman agents, but only through `TradeDesk`, which refuses (with the largest allowed quantity) a buy outside the target or beyond its weight plus the band, beyond the SMALLER of `buying_power` and cash plus this run's sell proceeds less this run's buys, a sell of a position this strategy never ordered (`traded` is recorded BEFORE `submit_order`), above held minus open sells, or below a target weight, and any sell after the first buy. `submit_target` enforces in code that a holding in a higher value tier never gets a smaller weight than one in a lower tier; the suggested weights are `CongressParams.tier_weight_base ** tier` (1.5) because dollar midpoints are too far apart to size a book on.

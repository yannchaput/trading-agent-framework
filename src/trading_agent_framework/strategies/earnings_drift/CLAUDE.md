# strategies/earnings_drift/ -- post-earnings announcement drift

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `earnings_drift/` (`EarningsDriftStrategy` in `agent_earnings_drift.py`, registered as `"earnings_drift"` (agent, 1-year window) and `"earnings_drift_baseline"` (`DriftParams(agent_enabled=False)`, 5-year window; env file `env/.env.earnings_drift_baseline.<mode>`, else `env/.env`)): post-earnings announcement drift. The cycle runs in `after_market_closes`, not on a tick. Pure `events` (SEC 8-K item 2.02, reaction session), `surprise` (Benzinga "EPS ... Estimate" headline parsing), `reaction` (daily-bar features), `screening` (gates), `fact_sheet`, `parameters` (`DriftParams`); `event_source.py` (the only SEC code, an in-memory event index), `scanner.py` (today's candidates; news is one query per event symbol over the reaction session, from the previous close to the reaction close and never past now (`events.news_window`, the same window for every event), read oldest first (`get_news(..., sort="asc")`, the optional `sort` of the `NewsProvider` seam: the provider answers the newest `news_limit` articles first, which cut the earnings headline of a busy name); the window is not anchored on the 8-K because SEC's acceptance time can trail the real release by ~4 h, though the reaction day itself is still derived from that time, so a midday release shifted late could land in the wrong session), `desk.py` (the only order code: the agent's `buy` / `set_trailing_stop` / `sell` tools, a trailing stop on every entry fill, the guardrails), `tools.py` (the agent's tools: the desk's four plus the clock-gated research tools), `book.py` (state file `data/<strategy name>_state_<mode>.json`: the agent and the baseline never share one; `trades.jsonl`, `decisions.jsonl` in the run directory).

## Gotchas

- **earnings_drift decides after the close, because of the backtest fill rule.** `BacktestBroker` skips the bar that is forming when an order arrives, so on daily bars an order sent at the 09:30 tick fills at the NEXT day's open, a session later than live. The cycle therefore runs in `after_market_closes` with `minutes_after_closing = 0`: an order sent at the exact close skips nothing and fills at the next open in both modes (Alpaca queues a DAY market order sent after hours). Paper/live first wait `live_bar_delay_seconds` (300) for the final daily bar. `on_trading_iteration` raises a `FatalStrategyError` recorded by the previous cycle (3 agent failures, a run that raised included, or 3 hollow scans in a backtest; paper/live only log), because the executor swallows exceptions from every other hook; in paper/live it then runs `Desk.recover()` (settle missed fills, take a positions snapshot, back up the stops; a trade whose position is absent or unknown gets no stop, since `_suspect` is memory only), so an entry filled at the open during a restart gets its stop at once. A failed scan counts as a hollow scan, and `Desk.begin_session` keeps the trading dates it already knows when given none (plus today), so max-hold keeps counting. The agent places its own orders, but only through the desk's tools: `buy` (candidates only, whole shares up to `max_quantity`, a free slot, `trail_percent` in [3, 15]), `set_trailing_stop` (tighten-only), `sell`; each violation returns `{"error": ...}` and logs `guardrail order_limits`. Code guardrails, each logging `guardrail <name>`: `max_hold` (sold when `sessions_held` (entry session through today, both included) reaches 10, never stated in the prompt), `stop_backstop` (a missing stop is placed again; a stop refused twice becomes a market sell), `orphan`, `baseline`. The desk never trusts one broker answer to say a position or order is gone. `buy` records the symbol in `traded_symbols` BEFORE `submit_order` (an order the client raised on may still have reached the broker); orphan adoption only adopts a real position of a symbol this strategy once traded, and a working trailing sell for it becomes its stop. A trade whose position is absent from the broker's positions list (one snapshot per reconcile) is closed as `unknown` only when absent on TWO consecutive reconciles (IBKR's portfolio cache can be empty after a reconnect); a suspect trade (absent once, and kept suspect when the positions fetch fails) gets no new stop and no max-hold sale that cycle, and `sell` / `set_trailing_stop` refuse it. Only LONG positions count (IBKR reports a short as a positive quantity with `side=SHORT`). A failed order lookup (as opposed to an unknown order) is never read as "missing": the trade is skipped for the cycle (`_fetch`, `_release_stop`). A stop whose cancel times out stays tracked and is placed again if its late CANCELED arrives. The desk holds one re-entrant lock: tools may run on parallel LangGraph threads. In backtests the entry session has no stop (the fill hook places it at that bar's close); live, the hook places it seconds after the open. Reaction sessions take every close as 16:00 ET (early closes are a known limit). Paper/live bars are IEX (~3% of consolidated volume): the scanner scales `min_dollar_volume` by `live_volume_share` (0.03) there, 1.0 in SIP backtests. A backtest loads SEC events once, with the run's end as the cache's freshness `as_of`, so a submissions file fetched before the end is refreshed.

# strategies/common/ -- code shared between strategies

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `strategies/common/` -- code shared between strategies, imported from there (no re-export shims; docs under `docs/superpowers/` still name the old locations): `scoring.py` (**pure** momentum scoring: `compute_return_from_prices`, `annualized_volatility`, `momentum_score`, `apply_filters`, `momentum_inputs`, then `score_stock` -> `MomentumRow` (`None` when filtered out or without a volatility, which cross_momentum would still rank but bull_bear cannot gate on `max_volatility` or show in its fact sheet) and `rank` -> `RankedRow`), `rebalancer.py` (`in_flight_quantities(open_orders)` -> (buys, sells), the unfilled quantity per symbol of open orders, also used by cross_momentum; `Rebalancer`, typed against the `RebalanceParams` protocol: `parking_symbol`, `rebalance_band`, `min_trade_pct`, `cash_buffer`; sells first, then buys, then SHV; a sell's log line ends with an estimated P&L against the position's `avg_fill_price` at the quoted price (`sell 100 B @ $25.00 (not in the target portfolio, est. P&L +$500.00 / +25.0%)`; omitted when the broker reports no cost or the price is unknown); **the cash invariant**: the account is read ONCE, before positions, open orders and any order, `cash` is never read again, and sell proceeds are added to that pre-sell snapshot, so a sell of this run that fills within seconds is counted once, and an earlier sell that has already filled (proceeds in the snapshot, no longer open) is not credited again -- reading the account afterwards double-counted it (a bug that hit congress_trades and earnings_drift); `buying_power` is re-read after the sells but only inside `min()`, and in paper/live only once the stock sells have FILLED (`strategy.wait_for_orders_execution`, `Rebalancer(fill_wait_seconds=30)`; a live broker credits buying power on a fill, not on acceptance: read 350 ms early, the 2026-10-27 bull_bear VSXY buy was skipped with "No cash left for buying"; a timeout warns and sizes on buying power as it stands; a backtest never waits, its buying power already credits a submitted sell and a wait would only move the simulated clock). The invariant does NOT cover an earlier open BUY that fills between the account read and the open-order read (its cost leaves `incoming` while the snapshot still holds the pre-fill cash); the `buying_power` re-read inside `min()` bounds that on a cash account only; pinned by two live-fill tests in `tests/strategies/common/test_common_rebalancer.py`; **an unknown outcome** (`BrokerUncertainError`, Tastytrade): the order is kept by the broker, never resent and never counted as refused (no buying-power resync): `PlacedOrder.confirmed=False`, an unknown buy's cost stays deducted from the available cash, an unknown sell (stock or SHV) adds no proceeds and is not waited on; **Known limitation: a "phantom" unknown order is not resolved on this path.** `TastytradeBroker` resolves an unknown write only from `pull_order`/`pull_orders`/`cancel_order`/`modify_order` and from `reconcile` (run only after an account-stream reconnect); none is called by bull_bear, bill_ackman or cross_momentum. An unknown order Tastytrade really created is adopted when the stream reports it. A phantom one (the POST failed, Tastytrade never created it) produces no stream event and stays tracked as SUBMITTED (unprocessed, so `get_active_orders()` returns it) until the process restarts (the tracker is in memory; `sync_open_orders` adopts only orders Tastytrade lists) or the stream happens to reconnect. Meanwhile a phantom BUY counts as in flight (that symbol is skipped and its cost held back each review) and a phantom SELL makes the holding unsellable ("already being sold"), so a forced exit or dropped stock is never sold again. Workaround until fixed: when the WARNING "outcome unknown at the broker" appears, check the Tastytrade account and, if the order is not there, restart the strategy.), `portfolio.py` (**pure** `TargetPortfolio`, `target_portfolio`), `sessions.py` (**pure** `completed_bars`, `parse_rebalance_time`), `yahoo_daily_bars.py` (`YahooDailyBars`, the one batched Yahoo download of paper/live daily bars), `sector_provider.py` (`SectorProvider`: yfinance sectors cached per instance, `"UNKNOWN"` on any failure, not point-in-time). Used by cross_momentum, bill_ackman and bull_bear.
- `trade_desk.py`, `handoff.py`, `run_log.py` (moved from congress_trades, shared with it and insider_trades): `TradeDesk(strategy, params: DeskParams, *, log_tag)` (`DeskParams` protocol: `rebalance_band`, `min_trade_pct`, `order_wait_seconds`) is the only order code of those strategies, `log_tag` prefixes its log lines (`[congress_trades] ...`) and is required; it is built with `begin_run(target | None, traded)`: with no target (`has_target` False) `place_order` refuses with `no target yet: call submit_target first` before reading the account and `audit()` has nothing to compare against, until `set_target` installs one WITHOUT clearing the orders placed or `traded`. `handoff.py` holds `HandoffError`, `OrderView`, `OrderReport`, `validate_report` and the public field readers `items`, `key`, `text`, `weight` (no `from __future__ import annotations`: it sits next to tool closures); `run_log.py` holds `RunLog(path | None).append(record)` (`runs.jsonl`, never raises on I/O).
- **The `min_price` / `min_dollar_volume` filters read what a stock actually traded at.** `momentum_inputs` / `score_stock` take `traded_closes=` and `traded_volumes=` (`yahoo.traded_series(frame)`, cut after `completed_bars(...).tail(...)`, `None` unless the frame has both `traded_close` and `traded_volume`); with both, `price` is the last traded close and `avg_dollar_volume` the mean of each of the last 20 sessions' traded close x traded volume (a last close x average volume would mix pre- and post-split share counts for 20 sessions after a split), while returns and volatility always come from the adjusted closes (so momentum is unchanged). Without them (an Alpaca frame, an `auto_adjust=True` parse) the adjusted series feed the filters as before. Why: the adjusted close is split- and dividend-adjusted back from today, so the filters saw prices no one ever traded at. NVDA printed about $20 in early 2015 but about $0.50 adjusted, so the $10 filter dropped it until mid-2020; a stock yielding 3% a year looks about 35% less liquid 15 years back. `YahooDailyBars` (paper/live) downloads the same `auto_adjust=False, actions=True` shape as the backtest (`backtesting/CLAUDE.md`).

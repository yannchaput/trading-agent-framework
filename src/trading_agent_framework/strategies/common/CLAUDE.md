# strategies/common/ -- code shared between strategies

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `strategies/common/` -- code shared between strategies, imported from there (no re-export shims; docs under `docs/superpowers/` still name the old locations): `scoring.py` (**pure** momentum scoring: `compute_return_from_prices`, `annualized_volatility`, `momentum_score`, `apply_filters`, `momentum_inputs`, then `score_stock` -> `MomentumRow` (`None` when filtered out or without a volatility, which cross_momentum would still rank but bull_bear cannot size) and `rank` -> `RankedRow`), `rebalancer.py` (`Rebalancer`, typed against the `RebalanceParams` protocol: `parking_symbol`, `rebalance_band`, `min_trade_pct`, `cash_buffer`; sells first, then buys, then SHV; a sell's log line ends with an estimated P&L against the position's `avg_fill_price` at the quoted price (`sell 100 B @ $25.00 (not in the target portfolio, est. P&L +$500.00 / +25.0%)`; omitted when the broker reports no cost or the price is unknown); **the cash invariant**: the account is read ONCE, before positions, open orders and any order, `cash` is never read again, and sell proceeds are added to that pre-sell snapshot, so a sell of this run that fills within seconds is counted once, and an earlier sell that has already filled (proceeds in the snapshot, no longer open) is not credited again -- reading the account afterwards double-counted it (a bug that hit congress_trades and earnings_drift); `buying_power` is re-read after the sells but only inside `min()`, and in paper/live only once the stock sells have FILLED (`strategy.wait_for_orders_execution`, `Rebalancer(fill_wait_seconds=30)`; a live broker credits buying power on a fill, not on acceptance: read 350 ms early, the 2026-10-27 bull_bear VSXY buy was skipped with "No cash left for buying"; a timeout warns and sizes on buying power as it stands; a backtest never waits, its buying power already credits a submitted sell and a wait would only move the simulated clock). The invariant does NOT cover an earlier open BUY that fills between the account read and the open-order read (its cost leaves `incoming` while the snapshot still holds the pre-fill cash); the `buying_power` re-read inside `min()` bounds that on a cash account only; pinned by two live-fill tests in `tests/strategies/common/test_common_rebalancer.py`), `portfolio.py` (**pure** `TargetPortfolio`, `target_portfolio`), `sessions.py` (**pure** `completed_bars`, `parse_rebalance_time`), `yahoo_daily_bars.py` (`YahooDailyBars`, the one batched Yahoo download of paper/live daily bars), `sector_provider.py` (`SectorProvider`: yfinance sectors cached per instance, `"UNKNOWN"` on any failure, not point-in-time). Used by cross_momentum, bill_ackman and bull_bear.
- `trade_desk.py`, `handoff.py`, `run_log.py` (moved from congress_trades, shared with it and insider_trades): `TradeDesk(strategy, params: DeskParams, *, log_tag)` (`DeskParams` protocol: `rebalance_band`, `min_trade_pct`, `order_wait_seconds`) is the only order code of those strategies, `log_tag` prefixes its log lines (`[congress_trades] ...`) and is required; it is built with `begin_run(target | None, traded)`: with no target (`has_target` False) `place_order` refuses with `no target yet: call submit_target first` before reading the account and `audit()` has nothing to compare against, until `set_target` installs one WITHOUT clearing the orders placed or `traded`. `handoff.py` holds `HandoffError`, `OrderView`, `OrderReport`, `validate_report` and the public field readers `items`, `key`, `text`, `weight` (no `from __future__ import annotations`: it sits next to tool closures); `run_log.py` holds `RunLog(path | None).append(record)` (`runs.jsonl`, never raises on I/O).

# strategies/common/ -- code shared between strategies

> Nested `CLAUDE.md`; project-wide rules are in the root `CLAUDE.md`. Paths are relative to `src/trading_agent_framework/` unless they start with `tests/`, `scripts/` or `docs/`.

## Architecture

- `strategies/common/` -- code shared between strategies, imported from there (no re-export shims; docs under `docs/superpowers/` still name the old locations): `scoring.py` (**pure** momentum scoring: `compute_return_from_prices`, `annualized_volatility`, `momentum_score`, `apply_filters`, `momentum_inputs`, then `score_stock` -> `MomentumRow` (`None` when filtered out or without a volatility, which cross_momentum would still rank but bull_bear cannot gate on `max_volatility` or show in its fact sheet) and `rank` -> `RankedRow`), `stops.py` (`release_stop(strategy, stop_order_id, *, expected_cancels, wait_seconds, warn_prefix)` -> `Release(status, order, error)`, `StopRelease` GONE / FILLED / RELEASED / FAILED: cancels a working stop and waits before an exit sell, shared by the earnings_drift and vwap_pullback desks; the id is in `expected_cancels` during the cancel and **discarded again on a cancel error or a timeout**, so a late CANCELED reaches the desk's stop path; a failed lookup is FAILED, never GONE; each desk books the partial fill and keeps its own return values), `rebalancer.py` (`in_flight_quantities(open_orders)` -> (buys, sells), the unfilled quantity per symbol of open orders, also used by cross_momentum; `Rebalancer`, typed against the `RebalanceParams` protocol: `parking_symbol`, `rebalance_band`, `min_trade_pct`, `cash_buffer`; sells first, then buys, then SHV; a sell's log line ends with an estimated P&L against the position's `avg_fill_price` at the quoted price (`sell 100 B @ $25.00 (not in the target portfolio, est. P&L +$500.00 / +25.0%)`; omitted when the broker reports no cost or the price is unknown); **the cash invariant**: the account is read ONCE, before positions, open orders and any order, `cash` is never read again, and sell proceeds are added to that pre-sell snapshot, so a sell of this run that fills within seconds is counted once, and an earlier sell that has already filled (proceeds in the snapshot, no longer open) is not credited again -- reading the account afterwards double-counted it (a bug that hit congress_trades and earnings_drift); `buying_power` is re-read after the sells but only inside `min()`, and in paper/live only once the stock sells have FILLED (`strategy.wait_for_orders_execution`, `Rebalancer(fill_wait_seconds=30)`; a live broker credits buying power on a fill, not on acceptance: read 350 ms early, the 2026-10-27 bull_bear VSXY buy was skipped with "No cash left for buying"; a timeout warns and sizes on buying power as it stands; a backtest never waits, its buying power already credits a submitted sell and a wait would only move the simulated clock). The invariant does NOT cover an earlier open BUY that fills between the account read and the open-order read (its cost leaves `incoming` while the snapshot still holds the pre-fill cash); the `buying_power` re-read inside `min()` bounds that on a cash account only; pinned by two live-fill tests in `tests/strategies/common/test_common_rebalancer.py`; **an unknown outcome** (`BrokerUncertainError`, Tastytrade): the order is kept by the broker, never resent and never counted as refused (no buying-power resync): `PlacedOrder.confirmed=False`, an unknown buy's cost stays deducted from the available cash, an unknown sell (stock or SHV) adds no proceeds and is not waited on; **A "phantom" unknown order (the POST failed, Tastytrade never created it) is settled before every tick.** It produces no stream event and stays tracked as SUBMITTED (unprocessed, so `get_active_orders()` returns it, and a phantom BUY would be counted as in flight and a phantom SELL would make the holding unsellable), so the executor calls `Broker.settle_unknown_orders()` before each tick (`core/CLAUDE.md`): `TastytradeBroker` looks the order up, adopts it if it exists and fails it after two misses at least 30 s apart, never resending it. With daily ticks a phantom from Tuesday's rebalance fails by Thursday, before the next Tuesday. Fallback if it ever stays: check the Tastytrade account and restart the strategy (the tracker is in memory).), `portfolio.py` (**pure** `TargetPortfolio`, `target_portfolio`), `sessions.py` (**pure** `completed_bars`, `parse_rebalance_time`), `yahoo_daily_bars.py` (`YahooDailyBars`, the one batched Yahoo download of paper/live daily bars; the `BarsSource` protocol; `fetch_usable_batch(source, universe, *, extras, today, held, min_coverage, retry_delays, sleep, on_retry)`, the retry and coverage check cross_momentum and bull_bear share: a batch is unusable when the lookup fails (`Yahoo lookup failed (...)`), covers under `min_coverage` of the universe only (`extras` such as SPY are requested but not counted) or misses a held stock that is in the universe (`held` is read only once coverage passes; a holding outside the universe is ignored); `on_retry(problem, delay)` then `sleep(delay)` after each failure, `UnusableBatch(problem)` after the last; each caller keeps its own log wording and its own sleep), `sector_provider.py` (`SectorProvider`: yfinance sectors cached per instance, `"UNKNOWN"` on any failure, not point-in-time). Used by cross_momentum, bill_ackman and bull_bear.
- `trade_desk.py`, `handoff.py`, `run_log.py` (moved from congress_trades, shared with it and insider_trades): `TradeDesk(strategy, params: DeskParams, *, log_tag)` (`DeskParams` protocol: `rebalance_band`, `min_trade_pct`, `order_wait_seconds`) is the only order code of those strategies, `log_tag` prefixes its log lines (`[congress_trades] ...`) and is required; it is built with `begin_run(target | None, traded)`: with no target (`has_target` False) `place_order` refuses with `no target yet: call submit_target first` before reading the account and `audit()` has nothing to compare against, until `set_target` installs one WITHOUT clearing the orders placed or `traded`. `handoff.py` holds `HandoffError`, `OrderView`, `OrderReport`, `validate_report`, the public field readers `items`, `key`, `required_text`/`optional_text` (take the field name), `text` (the `reason` field, `required=`), `weight(item, ticker, *, example="0.08")` and `covering(raw, expected, *, what, field="symbol", unknown, missing)` (one `(key, item)` per expected key in submission order, all key/unknown/duplicate checks first, then `missing`; used by bull_bear only, because bill_ackman, congress and insider interleave per-item checks with the key checks, so `covering` would change which error the model sees first), and `SubmitRecorder` (the base of all four strategies' recorders: `TOOL_NAMES`, `NOT_EXPECTED_SUFFIX`, `ALREADY_RECORDED`, `_arm`, `submit`, `_validate`, `_fail`, `submitted`, `submission`, `missing_tool`) (no `from __future__ import annotations`: it sits next to tool closures); `run_log.py` holds `RunLog(path | Callable[[], Path | None] | None, *, what="run log").append(record)` (the one JSONL run log: `runs.jsonl`, `reviews.jsonl`, `trades.jsonl`, `decisions.jsonl`; a callable path is read at every append; it serializes before opening and never raises on I/O or serialization, logging `<what> <path> could not be written`). `json_state.py` holds `atomic_write_json(path, payload, *, log, what="state") -> bool` (serialize first, mkstemp, replace; logs `<what> could not be saved to <path>` and returns False; also used by the bill_ackman annual-figures and split caches), the state validators `is_int`/`is_weight`/`valid_strings`/`valid_weights`, `InvalidState` and `JsonStateStore[S]` (a missing file is `empty()`, an unreadable or invalid one warns and is empty; `decode(raw)` gets the whole dict and raises `InvalidState` to reject it; `accepts` lists the readable versions, `save` always writes `version`; `fresh=True` wipes in the constructor, so a strategy builds `StateStore(self.state_file("<name>"), fresh=self.is_backtesting)` in `initialize`). Each strategy's `StateStore` subclasses it.
- `cooldowns.py` (**pure** `advance_cooldowns(current, *, started, length)`, used by bill_ackman and bull_bear).
- `pipeline.py` (the skeleton of the four agent pipelines: `AckmanPipeline`, `BullBearPipeline`, `CongressPipeline`, `InsiderPipeline`): `ReviewPipeline[S]` is a template. Its `run()` loads the state, builds the record (`date`, `run_id`, then `RECORD_FLAG`: `abandoned` False/True for the review pipelines, `outcome` None/`"abandoned"` for congress and insider), calls `_begin()` (reset what a failure is attributed to; a no-op for bull_bear, which resets `_stage` in `_review`) and the body `_run(now, state, record) -> RunOutcome`. An abandonment is a `StageAbandoned(stage, message)` (stage = its `.stage`), a `DATA_ERRORS` exception (stage `filings`) or a `BrokerError`/`BacktestError` (stage `execution` when `_executing()` else `broker`; `ConfigurationError` propagates): it bumps the streak, logs `<LOG_PREFIX><WHAT> abandoned at the <stage> stage (streak N): <error>`, saves what `_on_abandoned(state, streak, stage)` returns and appends `{**record, <flag>: abandoned, stage, error, abandoned_streak, **extra}`. The four `test_abandoned_record_unchanged` tests pin the log line, the record (key order included) and the saved state. Also here: `AgentLike`/`AgentLookup` (bull_bear's subclass `AgentLike` adds `max_steps`), `RunOutcome(completed, abandoned_streak)`. Concrete pending-trade steps only congress_trades and insider_trades call (they take the `TradeDesk`/state as arguments; bill_ackman and bull_bear gain nothing): `PendingTrade`/`valid_pending`/`decode_pending` (the state modules import them), `_orders_record(desk)`, `_at_target(before)` (logs the at-target line, True when nothing is off target), `_audited(desk, record)` (the after-audit record and warnings), `_give_up_pending`, `_finish_pending` and `_abandoned_with_pending` (the `_on_abandoned` body). Each strategy keeps its own log lines around them. `_run_stage`, `retry_prompt` and each body stay in the strategy: the four differ too much to share them.
- `universe_history.py` (pure apart from `save`/`load`): the point-in-time stock universe cross_momentum and bull_bear backtest on. `UniverseHistory` (`built`, `pool_date`, `top_n`, `min_price`, `min_dollar_volume`, `lookback`, `months`: "YYYY-MM" -> symbols, best first; plus `pool_size`, `unanswered`, `bars_absent`, which describe the latest build's pool and default to 0/empty for older files) with `on(day)` (the list of `day`'s month; **a missing month raises `UniverseHistoryError`, never another month's list**), `covers`, `union` (every symbol of a window, for the preload) and `save`/`load` (`save` writes a temp file and renames it). `monthly_lists` ranks each month on data dated **before its first session only**: the mean of `traded_close * traded_volume` (split-unadjusted, from `parse_yahoo_frame`) over the 63 sessions before it, kept when the last such traded close is at least `min_price` ($10) and the mean at least `min_dollar_volume` ($20M) (`universe_params.py`), top 1,200. A symbol needs 63 prior rows and its last one within the 10 sessions before the month's first (`_MAX_STALE_SESSIONS`), so a stock that stopped trading is not ranked on its old volume. Why: the universe file is built today and holds today's winners, so a backtest on it trades stocks that had already won. **Residual bias: stocks delisted inside the window are absent from Yahoo, so from every list.** The build is `ensure_universe_history` in `batch_us_stock_universe.py` (`strategies/cross_momentum/CLAUDE.md`).
- `universe_params.py`: `MIN_PRICE`, `MIN_DOLLAR_VOLUME`, `MIN_MARKET_CAP`, the one home of the universe's liquidity thresholds; the batch module filters on them and cross_momentum's `CONFIG` reads them (change them here only). `universe_history.py` also holds `market_day` (a backtest bound's market-time date), `window_symbols(history, start, end, exclude=)` (the window's union, for the preload) and `month_universe(history, day, exclude=)` (a review's list, in rank order; a missing month raises `FatalStrategyError`, since the executor swallows anything else as a failed tick).
- `batch_us_stock_universe.py` (`uv run batch-universe`; moved here from cross_momentum, it no longer imports any strategy): the live universe batch and the point-in-time history build (`ensure_universe_history`, `build_history_pool`, `HistoryPool`). Its shared yfinance state is module-level (`rate_limit_gate`, `_semaphore`); tests replace `rate_limit_gate` with `monkeypatch.setattr` and the code reads the name at call time. `_etf_symbols(..., strict=)` is the IWB/IWM/VTI union: lenient for the live batch (`get_extra_universe_symbols`), strict for the history pool. `download_batch`, `HISTORY_BATCH_SIZE` and `MAX_ABSENT_FRACTION` are public because `universe_backtest_data.py` uses them.
- `universe_backtest_data.py`: `UniverseBacktestData`, the batched, retried Yahoo preload of a point-in-time backtest, and `universe_parameters` (the `parameters["universe"]` record).
- **The `min_price` / `min_dollar_volume` filters read what a stock actually traded at.** `momentum_inputs` / `score_stock` take `traded_closes=` and `traded_volumes=` (`yahoo.traded_series(frame)`, cut after `completed_bars(...).tail(...)`, `None` unless the frame has both `traded_close` and `traded_volume`); with both, `price` is the last traded close and `avg_dollar_volume` the mean of each of the last 20 sessions' traded close x traded volume (a last close x average volume would mix pre- and post-split share counts for 20 sessions after a split), while returns and volatility always come from the adjusted closes (so momentum is unchanged). Without them (an Alpaca frame, an `auto_adjust=True` parse) the adjusted series feed the filters as before. Why: the adjusted close is split- and dividend-adjusted back from today, so the filters saw prices no one ever traded at. NVDA printed about $20 in early 2015 but about $0.50 adjusted, so the $10 filter dropped it until mid-2020; a stock yielding 3% a year looks about 35% less liquid 15 years back. `YahooDailyBars` (paper/live) downloads the same `auto_adjust=False, actions=True` shape as the backtest (`backtesting/CLAUDE.md`).
